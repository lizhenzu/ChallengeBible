# 03. 업무 규칙

> 현행 동작을 코드에서 직접 확인해 적었다(2026-10-21).
> **[설정]** = 영역 관리자가 바꿀 수 있는 값(D10), **[고정]** = 플랫폼 규칙, **[현행 문제]** = 새 설계에서 고칠 점.
> 규칙 번호(R-xx)는 새 프로젝트의 테스트 케이스 이름으로 쓴다.

## 1. 날짜와 시간

| # | 규칙 |
|---|---|
| R-01 | 모든 "오늘"은 **영역의 시간대** 기준이다. [설정: 영역 시간대, 기본 Asia/Seoul] |
| R-02 | 저장은 UTC 시각 + **미션 대상일(날짜만)** 을 따로 둔다. 대상일은 영역 시간대의 날짜다. |
| R-03 | 주(週)는 **일요일 시작**이다(현행 달력 · "이번 주 띠" 모두 일요일 시작). [설정 후보: 주 시작 요일] |
| [현행 문제] | 앱은 한국 시간, DB 함수는 `GETDATE()`(서버 시간)를 섞어 쓴다. 점수 집계 함수는 날짜 목록을 **'2026-01-01' 부터 하드코딩**해서 만든다 → 해가 바뀌면 고쳐야 한다. |

## 3. 미션 4종과 점수

### 3-1. 말씀 읽기 (Word) — 매일
| # | 규칙 |
|---|---|
| R-20 | 항목 2개: **내가 읽기**(+1), **부모님께 읽어드리기**(+1). 하루 최대 2점. [설정: 항목별 점수] |
| R-21 | 두 항목은 **따로** 누를 수 있고, 한 번 켠 항목은 **꺼지지 않는다**(누적 OR). 같은 항목을 다시 눌러도 점수 증가 없음. |
| R-22 | 그날 오늘의 말씀이 없으면 미션을 할 수 없다. |
| R-23 | 아무 항목도 고르지 않고 저장하면 거절("체크를 선택해 주세요"). |
| 참고 | "말씀 미션 완료"는 둘 중 하나라도 켜진 상태. |

### 3-2. 기도 (Prayer) — 매일
| # | 규칙 |
|---|---|
| R-30 | 항목 2개: **나를 위해**(+1), **가족·친구를 위해**(+1). 하루 최대 2점. [설정: 항목별 이름 · 점수 · 사용 여부] (ADR 0047 — 처음 정한 나 · 부모님 · 친구(0점)에서 바뀜)<br>공용 기도는 **날짜 번호 1 ~ 31** 로 두고 매달 같은 날짜에 같은 기도를 보여 준다. 부서가 그날 기도를 넣으면 **그날에만** 그것이 먼저다(0053). |
| R-31 | 한 번 켠 항목은 꺼지지 않는다(누적 OR). |
| R-32 | "기도 완료"는 켜진 항목 중 하나라도 한 상태. 기도문의 `{이름}` 자리는 이름을 넣지 않고 **"○○"로 강조**해 보여 준다. 나를 위해서도, 다른 사람을 위해서도 드리는 기도라서다(ADR 0054, 0047 의 "참여자 이름으로 바꿈"을 바꿈). |
| [현행 문제] | 화면 문구는 "부모님이나 친구를 위해"와 "친구를 위해"가 섞여 있다. 점수 계산은 `ToParent` 만 +1, `ToFriend` 는 저장만 하고 점수 없음. 새 설계에서는 항목 이름과 점수를 설정으로 명확히. |

### 3-3. 퀴즈 (Quiz) — 매일
| # | 규칙 |
|---|---|
| R-40 | 하루 1문제. **정답이면 +1**. 하루 최대 1점. [설정: 점수] |
| R-41 | 하루 최대 **2번** 시도. 이미 정답이면 더 시도할 수 없음. 2번 다 틀리면 그날은 끝. [설정: 시도 횟수] |
| R-42 | 시도마다 고른 답을 기록한다(나중에 "내가 고른 자리" 표시). |
| R-43 | 정답 판정은 서버에서, 저장된 정답과 비교한다. 객관식은 보기 번호, 주관식은 정규화한 문자열 비교. |
| R-44 | 응답 문구: 정답 → "정답! +1점", 1차 오답 → "오답이에요 (1/2) 한 번 더", 2차 오답 → "오늘은 2번 도전했어요. 내일 새 퀴즈에 도전" |
| [현행 문제] | 정답 비교가 **문자열 완전 일치**(`AnswerQ = CorrectAnswer`)라 주관식 띄어쓰기 · 대소문자에 약하다. |

### 3-4. 암송 (Recite) — 매주
| # | 규칙 |
|---|---|
| R-50 | 이번 주 암송 구절 1개(일요일 ~ 토요일). **주 1회 +1**. [설정: 점수]<br>공용 암송은 **주 번호 1 ~ 55** 로 두고 해마다 같은 순서로 돈다(그해 첫 일요일에 시작하는 주가 1주). 부서가 그 주 암송을 넣으면 **그해 그 주에만** 그것이 먼저이고, 해가 바뀌면 공용으로 돌아간다(0052). |
| R-51 | 같은 주 암송은 **한 번만** 인정된다(이미 했으면 "이번 주 암송은 이미 완료했어요"). |
| R-52 | 수행은 인정 기간(R-10) 안의 날짜에서만. |
| R-53 | 점수는 **실제 암송한 미션 대상일**에 기록한다(D24). "주 1회"는 그 주(암송 콘텐츠 기간)에 대해 판단. 달력의 완주일 판단(R-72)에서는 그 날이 속한 주의 암송을 했으면 완료로 본다. |
| [현행 차이] | 현행은 점수를 **그 주의 시작일**에 기록한다. 목요일에 암송해도 지난 일요일 점수로 들어가 인정 기간 밖 날짜에 점수가 생긴다. 새 설계는 이 동작을 따르지 않는다. |
| 참고 | 암송 화면은 언어 설정과 관계없이 한국어로만 보여 준다(현행). |

### 3-5. 하루 점수와 합계
| # | 규칙 |
|---|---|
| R-60 | 하루 점수 = 말씀(0~2) + 기도(0~2) + 퀴즈(0~1) + 암송(0~1) → **하루 최대 6점**(암송한 날 기준). 기본값 기준. |
| R-61 | 같은 날 같은 항목이 중복 저장돼도 **두 번 세지 않는다**(현행 함수가 날짜별 MAX 로 방어). 새 설계에서는 **고유 제약**으로 원천 차단. |
| R-62 | 시즌 점수 = 시즌 시작일 ~ (진행 중이면 오늘, 지난 시즌이면 시즌 끝날) 하루 점수 합. 시즌은 기본 1월 1일 시작 1년, 영역이 시작일 변경 가능(D17). |
| R-63 | 점수는 **수행 기록에서 파생**된다. 새 설계에서는 수행 시 **점수 원장에 한 줄**을 쓰고, 합계는 원장 합(또는 집계 테이블). |
| R-64 | 규칙 값이 바뀌어도 **이미 쌓인 점수는 바뀌지 않는다**(원장에 당시 점수를 기록). |
| R-65 | 점수를 얻으면 "+N 점" 축하 메시지와 "올해 총 X점"을 보여 준다. 추가 점수가 0이면(이미 한 항목) 단계 검사도 하지 않는다. |

## 4. 달력과 기록 보기

| # | 규칙 |

| R-75 | 날짜를 눌러 지난 날짜로 이동하면 "다른 날짜 미션을 보고 있습니다" 안내를 띄운다. |
| R-76 | 내 점수 화면: 월별 하루 점수 표(말씀 · 퀴즈 · 기도 · 암송 · 합계). |

## 5. 순위 · 참여자 (기능 스위치: 순위)

| # | 규칙 |
|---|---|
| R-80 | 참여자 목록 = 시즌 점수 > 0 인 참여자. 점수 내림차순, 같으면 이름순. |
| R-81 | 카드에 표시: 이름, 프로필 사진, 그룹 라벨(있으면), 시즌 점수, **목표 대비 달성률**(0~100%로 자름), 마지막 참여일, 연속 참여일, 가족팀 이름(있으면). |
| R-82 | 목표 점수 = 가장 높은 축하 단계 점수(현행 8,000). [설정] |
| R-83 | **연속 참여일**: 마지막 점수 획득일부터 거꾸로, 하루도 빠짐없이 점수가 있었던 날 수. 마지막 점수일이 오늘이 아니어도 그 날 기준으로 센다(현행). |
| R-84 | 본인 카드는 강조 표시. |
| [현행 문제] | 참여자를 학생 · 교사 · 부모로 나누는 기준이 "반 정보가 있으면 학생, 역할 이름이 없으면 부모, 나머지 교사"라는 추측이다. 새 설계에서는 소속의 역할로 명확히. |
| [현행 문제] | 순위 계산이 사용자마다 DB 함수를 두 번(점수 · 연속일) 호출 → 사람이 늘면 느려진다. 집계 테이블로. |

## 6. 가족팀 (기능 스위치: 가족팀)

| # | 규칙 |
|---|---|
| R-90 | 가족팀은 영역 관리자가 만든다(이름, 메모, 활성 여부). 구성원은 **같은 영역의 참여자**만. |
| R-91 | 구성원 속성: 관계(학생 0 · 엄마 1 · 아빠 2 · 할머니 3 · 할아버지 4 · 기타), 표시 순서, 활성 여부. 한 참여자는 한 시즌에 **한 팀**에만. |

| R-93 | 팀 이름이 비면 "{대표 학생 이름} 가족". 대표 학생 = 관계가 학생인 첫 구성원. |
| R-94 | 팀 카드: 팀 점수, 달성률, 구성원별 점수(가계도 형태), 마지막 참여일 = 구성원 중 가장 최근. |
| R-95 | 개인 순위에는 가족팀 구성원도 **그대로 나온다**(팀 소속 표시만 추가). |
| R-96 | **가족 단계**(시즌별): 기본 1,000 · 3,000 · 5,000 = 축하+보상(AWARD), 2,000 · 4,000 = 박수(APPLAUSE). 표시 문구 · 이모지 · 순서 · 활성 여부를 가진다. [설정] |
| R-97 | 팀 합산이 단계를 넘으면 홈 · 팀 화면에 축하 카드를 보여 준다. 관리자는 팀별로 특정 단계 카드를 숨길 수 있다. |
| 참고 | 보상(선물)은 범위 밖 — "가족 단계 도달" 이벤트만 낸다. |
| R-168 | 보호자(부모) 계정은 "가족과 함께할 부서"를 하나 고른다(부모가 결정). 그 부서에서만 참여자 · 가족팀 구성원이 되고, 다른 부서에서는 보호자로 보기만 한다. 바꾸면 이전 부서의 참여 · 가족팀 자리는 멈추고 기록은 남는다. 자동으로 정하지 않으며, 고르기 전에는 어느 부서에서도 참여자 · 가족팀이 될 수 없다(ADR 0046). |

## 9. 콘텐츠 결정 규칙 (D9)

| R-120 | 어떤 날짜의 콘텐츠 = **영역 덮어쓰기가 있으면 그것, 없으면 공용 콘텐츠**. 종류별(말씀 · 기도 · 퀴즈 · 암송)로 따로 판단. |
| R-121 | 하루에 종류별 콘텐츠는 **최대 1건**(고유 제약). 암송은 기간이 겹치지 않게. |
| R-122 | 콘텐츠가 없는 날은 그 미션을 "오늘은 없음"으로 보여 준다. 그 날은 **완주일이 될 수 없다**(D23, 현행과 같음). 관리자 화면에서 콘텐츠 빈 날을 미리 경고한다. |
| R-123 | 공개 여부(초안/공개)를 가진다. 공개된 것만 참여자에게 보인다. |
| R-124 | 이미 기록이 있는 콘텐츠를 지우거나 바꿔도 **과거 기록 · 점수는 유지**된다(기록은 당시 콘텐츠 ID · 버전을 가리킴). |

## 10. 테넌시 · 권한 규칙

| # | 규칙 |
|---|---|
| R-130 | 모든 요청은 주소의 영역 코드로 영역을 정하고, 로그인 계정이 그 영역에 **승인된 소속**이 있어야 한다(없으면 소속 신청 화면). |
| R-131 | 모든 조회 · 저장은 그 영역의 데이터로 제한된다 — **RLS 와 앱 전역 필터 이중**(D20). 다른 영역 ID 를 넣어도 결과는 "없음". |
| R-132 | 보호자는 **보호 관계로 연결된 참여자**의 기록만 볼 수 있다. |
| R-133 | 영역 관리자는 자기 영역의 소속 · 보호 관계 · 가족팀 · 설정 · 덮어쓰기 콘텐츠만 다룬다. |
| R-134 | 플랫폼 관리자의 영역 진입 · 대리 접속 · 설정 변경은 감사 로그에 남긴다(누가, 언제, 어느 영역, 무엇). |
| R-135 | 한 계정이 여러 영역에 소속되면 상단에서 **영역 전환**. 마지막으로 쓴 영역을 기억. |
| R-136 | **[폐지 — ADR 0031: 동의 확인 없이 승인만으로 미션]** 참여자 소속은 영역 관리자가 **"보호자 동의 확인"** 을 표시해야 미션 저장이 가능하다(D14). 확인 전에는 보기만. 확인 일시 · 확인자를 기록. |
| R-137 | 아이 가입 시 받는 개인정보는 이메일 · 비밀번호 · 이름(또는 별명)만(ADR 0050). 전화 · 생일 · 주소는 받지 않는다(D14). |
| R-138 | 한 계정이 같은 영역에서 **보호자 + 참여자** 역할을 함께 가질 수 있다. 점수는 참여자 역할로만 쌓인다(D15). |
| R-139 | **진급**: 새 영역 소속을 만들고 이전 영역의 소속 · 기록 · 점수 · 가족팀 구성원을 **완전 삭제**한다(지난 시즌 순위 · 통계에서도 사라짐). 새 영역은 0점부터(D16, D22). |

## 10-2. 성경통독 (프로그램: 도전!!!성경통독 — ADR 0039, 0040)

| # | 규칙 |
|---|---|
| R-150 | 영역은 프로그램(성경말씀 · 성경통독)을 하나 이상 켠다. 꺼진 프로그램의 화면 · API 는 404. |
| R-151 | 진도의 단위는 **장**이다. 장은 (1) 본문을 마지막 절까지 넘기면 자동 완료, (2) 책 목록에서 장을 눌러 바로 완료 — 두 길로 완료된다(ADR 0041). 장 완료 켜기 `PUT` · 끄기 `DELETE` 는 멱등. |
| R-152 | 읽은 절(넘긴 절, 장 완료 시 그 장 전체)은 성경 읽음 표시(0029)에도 기록한다. 해제는 연동하지 않는다. |
| R-153 | 계정마다 진행 중 회차는 하나. 1,189장을 모두 읽으면 회차 완료(완료일) + 다음 회차 자동 시작. |
| R-154 | 본인은 언제든 새 회차를 시작할 수 있다. 이전 회차는 미완료로 닫히고 기록은 남는다. |
| R-155 | 진도율 = 현재 회차 읽은 장 ÷ 1,189 (소수 첫째 자리). 완독 횟수 = 완료된 회차 수. |
| R-156 | 오늘 읽은 장 수 · 연속 읽은 날을 보여 준다. "오늘"은 접속한 영역의 시간대. |
| R-157 | 통독에는 점수가 없고, 성경말씀 점수와 무관하다. 참여자 현황의 진도율순 정렬은 허용한다(ADR 0041). |
| R-158 | 통독 기록은 계정에 붙어 진급 · 영역 변경과 무관하게 이어진다. |
| R-159 | 참여자 현황(이름 · 그룹 라벨/역할 · 진도율 · 회차 · 마지막 읽은 곳과 때 · 완독자 명예의 전당)은 기본으로 그 영역 소속원 모두에게 보인다. 영역이 "공개"를 끄면 관리자 · 교사만 본다. 다른 영역에는 보이지 않는다. |
| R-160 | 본문 화면은 읽기 단위(한 절 · 3절 · 5절 · 전체)만큼 보여 준다. 절마다 읽음 표시를 켜고 끌 수 있고, "이 페이지 모두 읽음"은 보이는 절을 한 번에 표시한다. **"다음 · 이전"으로 넘기기만 해서는 읽음 표시하지 않는다**(ADR 0042). |
| R-161 | 마지막으로 보던 위치(장 · 첫 절)를 회차별로 기억한다. "이어 읽기"는 그 위치, 없으면 마지막으로 완료한 장의 다음 장으로 간다. 보던 위치는 읽음 여부와 무관하다. |
| R-162 | 그 장의 모든 절이 그 회차에서 읽음이면 장은 자동 완료되고(R-151), 회차의 1,189장이 모두 완료되면 회차 완료(R-153). |
| R-163 | 성경 검색은 단어 · 구절로 본문을 찾는다. 결과는 번역을 고를 수 있다. |
| R-164 | 인기 검색어는 영역별로 모은다. 검색어와 시각만 남기고 누가 찾았는지는 남기지 않는다. |
| R-165 | 번역 "모두"는 개역개정 · 현대인의성경 · NIV 를 절마다 나란히 보여 준다. 없는 절은 그 번역 칸을 비운다. |
| R-166 | 장마다 듣기 · 해설 영상(유튜브)을 0개 이상 연결할 수 있다. 플랫폼 관리자가 넣는다(처음에는 Bible2 에서 옮겨 옴 — ADR 0043). 없으면 버튼을 숨긴다. |
| R-167 | 글자 크기는 − (5%씩) · + (10%씩)로 각각 5번까지, 75% ~ 150%. 가운데 비율을 누르면 100%. 본문 · 번역 줄 · 개요 · 요약만 커지고 그 기기에 기억한다(ADR 0043). |
