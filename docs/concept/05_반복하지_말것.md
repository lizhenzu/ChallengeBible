# 05. 현행 시스템에서 반복하지 말 것

> 지금 시스템에서 실제로 확인한 문제와, 새 설계에서 대신할 방법. (모두 2026-10-21 코드 · DB 기준)

| # | 현행 문제 | 영향 | 새 설계 |
|---|---|---|---|
| X-01 | **사람 키 3종 혼용**: 미션 기록은 `UserName`(아이디 문자열), 성경 진도는 `UserId`(GUID), 출석 · 반은 `PersonId`(정수) | 아이디 변경 시 기록이 끊김, 조인마다 변환 뷰 필요 | 참여자 키 **하나**(정수/GUID). 아이디는 계정 속성일 뿐 어떤 기록에도 쓰지 않음 |
| X-02 | **연도별 표 · 하드코딩**: `ClassInfo_2026`, `view_PersonMaster_2026`, 함수 안 `'2026-01-01'` | 해마다 코드 · DB 수정, 잊으면 점수 0 | 표 하나 + 시즌(날짜 범위). 연도 문자열 금지 |
| X-03 | **점수를 매번 함수로 재계산**: 사용자별 날짜 목록을 만들어 4개 기록 표를 조인(`ufn_GetUserClickHistory` → `ufn_DM2_GetUserDailyPoints`). 순위는 사용자 × 함수 2번 | 사용자 · 기간이 늘수록 느려짐, 스레드풀 늘려서 버팀 | **점수 원장**에 수행 시 기록 + **일별 · 시즌 집계 테이블**(증분 갱신) |
| X-04 | **중복 방지를 집계에서 처리**: 같은 날 같은 기록이 여러 줄 저장될 수 있어 `MAX`·`COUNT` 로 방어, `chcekYN='check'` 표시 | 데이터 신뢰 불가 | (참여자, 대상일, 미션 항목) **고유 제약**. 저장은 upsert |
| X-05 | **예/아니오를 문자열로**: `ToMe nvarchar(1)` 'y'/'n'/''(빈 값), 퀴즈 결과 't'/'f', 대소문자 섞임 | 비교마다 `UPPER(ISNULL())` | 항목별 행(있으면 수행) 또는 `bit` |
| X-06 | **규칙 하드코딩**: 점수(+1), 인정 기간(2일 차), 퀴즈 2회, 친구 0점이 C# · SQL · 화면 문구에 흩어짐 | 규칙 변경 = 코드 배포, 화면과 계산 불일치 | 규칙 설정(RuleSet) 한 곳, 화면 문구도 설정값으로 표시 |
| X-07 | **암송 점수 날짜 = 주 시작일**(실제 수행일 아님) | 인정 기간 밖 날짜에 점수 생김, 달력 혼란 | 실제 암송한 날에 기록(D24, R-53) |
| X-08 | **퀴즈 정답 문자열 완전 일치** | 주관식 오답 처리 | 객관식은 보기 ID, 주관식은 정규화 · 허용 답 목록 |
| X-09 | **서버 시간 · 한국 시간 혼용**(`GETDATE()` vs `GetKoreaNow()`) | 자정 근처 날짜 어긋남 | 저장 UTC + 대상일(영역 시간대), DB 에서 현재 시각 사용 금지 |
| X-10 | **역할 추측**: "반이 있으면 학생, 역할 이름이 없으면 부모, 아니면 교사" | 잘못된 표시 | 소속 역할 명시 |
| X-11 | **계정 이름 기반 권한 예외**("Basic"·"SuperAdmin" 아이디면 관리자) | 보안 · 유지보수 위험 | 역할 · 정책 기반 권한만 |
| X-12 | **오류 삼키기** `catch { }` 가 거의 모든 부가 기능에 | 화면이 0 · 빈칸, 원인 추적 불가 | 구조적 로깅 + 사용자에겐 안전한 안내 |
| X-13 | **화면 데이터 전달이 ViewBag · TempData 다발**(디버그 값까지 TempData 에) | 화면 · 서버 계약 불명확 | 화면별 모델(ViewModel) 또는 API DTO |
| X-14 | **동기 레거시 계층 혼용**(`Manage*`, `SharedComm` 정적 호출이 새 서비스 안에서 호출) | 테스트 · 비동기 불가 | 단일 서비스 계층, 전부 async, DI |
| X-15 | **세대별 중복 화면**(DailyMission2 · 3 · 4, `_bak` 파일) | 어느 것이 진짜인지 혼란 | 버전은 Git 으로, 화면 하나 |
| X-16 | **미션 · 선물 · 통합 점수 결합**: 미션 홈이 출석 · 세계관 · 묵상 · 전도 서비스를 불러 통합 점수 · 선물 금액까지 계산 | 기능 하나 바꾸면 미션 홈이 깨짐 | 미션 서비스는 자기 점수만. 나머지는 이벤트/API 로 바깥에서 |
| X-17 | **읽음 표시 API 가 토글뿐**(읽음 요청도 토글이라 이미 읽은 절에 "읽음"을 보내면 취소됨) | 이중 클릭 · 재시도 시 반대로 됨 | 멱등(idempotent) API: `PUT 읽음`, `DELETE 읽음` |
