# 06. 새 프로젝트 시작 안내

## 1. 준비
1. GitHub 에 새 저장소를 만든다. 예: `ChallengeBible` (비공개 권장).
2. PC 에 받는다. 예: `C:\WorkSpace\ChallengeBible`
3. 이 폴더(`docs/challenge-bible/`)를 새 저장소의 `docs/concept/` 로 복사한다.
4. Claude 데스크톱 앱에서 **새 저장소 폴더로 새 코드방**을 연다.

## 2. 새 저장소의 첫 CLAUDE.md (초안)
아래를 새 저장소 루트에 `CLAUDE.md` 로 두고 시작한다.

```markdown
# 도전 성경말씀 SaaS

## 제품
- 주일학교 아이들의 매일 성경 미션(말씀 · 기도 · 퀴즈 · 암송) + 점수 서비스
- 멀티테넌트 SaaS: 영역(부서) = 테넌트, 완전 격리. 플랫폼 관리자만 영역을 넘나듦
- 개념 명세: docs/concept/ (결정 사항 01, 용어 02, 업무 규칙 03, 화면 04, 금지 사항 05)

## 원칙
- 용어는 docs/concept/02_용어집.md 를 따른다
- 모든 업무 데이터는 TenantId 를 가진다. TenantId 없는 조회 · 저장 금지
- 점수 규칙 값은 코드에 쓰지 않고 RuleSet 에서 읽는다
- 날짜: 저장은 UTC, "오늘"은 영역 시간대. DB 의 GETDATE() 등 현재 시각 함수 금지
- docs/concept/05_반복하지_말것.md 의 항목을 어기지 않는다
- 업무 규칙(R-번호)마다 테스트를 둔다

## 기술
- ASP.NET Core (.NET 9), EF Core, SQL Server, PWA
- 호스팅: SmarterASP(site4now)

## 작업 방식
- 한국어로 답한다
- 설계 결정은 docs/design/ 에 ADR 로 남긴다
```

## 3. 설계 · 개발 순서 (권장)

| 단계 | 산출물 | 메모 |
|---|---|---|
| 0. DB 준비 | SmarterASP 제어판에서 **SQL Server 2019 이상**으로 새 DB 생성 (사용 가능 확인 완료 2026-10-21) | D18, D21. 현행 DB 서버(2014)는 쓰지 않음 |
| 1. 결정 기록 | ADR 문서 | D1 ~ D25 는 이미 확정 — ADR 로 옮겨 적기만 |
| 2. 도메인 모델 | 집합(Aggregate) · 엔터티 · 값 객체, 컨텍스트 경계(테넌시 / 콘텐츠 / 미션 · 점수 / 가족 · 순위) | 02 용어집 기준 |
| 3. 논리 설계 | ERD, 고유 제약 · 관계, 테넌트 키 규칙 | 05 문서 X-01 ~ X-05, X-18 ~ X-19 반영 |
| 4. 물리 설계 | DDL, 인덱스(TenantId 선두), RLS 정책, 집계 테이블, 마이그레이션 | |
| 5. API · 화면 계약 | 엔드포인트 목록, DTO, 권한 매트릭스 | 04 문서 화면 목록 기준 |
| 6. 화면 시안 | 휴대폰 우선 시안 → 확정 | 디자인 먼저, 코드 나중 |
| 7. 1차 구현 (MVP) | 계정 · 영역 · 소속 · 공용 콘텐츠 · 미션 4종 · 점수 · 달력 | 순위 · 가족팀 · 덮어쓰기는 2차 가능 |
| 8. 테스트 | R-번호별 테스트, **테넌트 격리 테스트**(다른 영역 ID 로 조회 · 저장 시도) | |
| 9. 배포 | SmarterASP 새 사이트, 마이그레이션 실행 절차, 백업 | |
| 10. 2차 | 순위, 가족팀, 영역 덮어쓰기, 보호자 화면, 외부 연동 이벤트 | |

## 4. 1차(MVP) 범위 제안
- 계정 가입 · 로그인, 영역 생성(플랫폼 관리자), 소속 신청 · 승인(영역 관리자)
- 공용 콘텐츠 4종 입력(플랫폼 관리자)
- 미션 4종 수행 + 인정 기간 + 점수 원장 + 하루 · 시즌 점수
- 미션 홈, 말씀 · 기도 · 퀴즈 · 암송 화면, 달력, 내 점수
- 규칙 설정은 플랫폼 기본값만(영역 변경은 2차)

## 5. 새 방에 처음 보낼 메시지 예시
> docs/concept/ 의 개념 명세를 모두 읽고, 결정 D1 ~ D25 를 docs/design/ 에 ADR 로 정리해 줘.
> 이해가 안 되거나 서로 부딪치는 부분이 있으면 하나씩 물어봐 줘. 그 다음 도메인 모델부터 시작하자.
