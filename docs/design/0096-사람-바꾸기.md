# 0096. 사람 바꾸기(가장 중 로그아웃 없이 다른 계정으로)

- 상태: 확정 (2026-11-14, 사용자 "모든 계정" → 시안 "확정")
- 더하는 것: 0067(플랫폼 관리자 가장), 0095(임시 시험 도구)
- 확정 시안: `docs/design/시안/사람바꾸기-시안.png`, 구현 캡처 `사람바꾸기-구현.png`
- 업무 규칙: R-300

## 맥락
시험할 때 관리자에서 특정인으로 들어간 뒤, 로그아웃 · 다시 로그인 없이 사람을 마음대로 바꾸고 싶다(사용자 2026-11-14).
가장(0067)은 계정 찾기 화면에서 한 사람씩만 들어가고, 시험 도구의 로그인 버튼은 관리자 흔적 없이 그 계정으로 완전히 로그인했다.

## 결정
1. 가장 중 띠(보라)에 **[사람 바꾸기]**. 누르면 화면 위 창(휴대폰은 아래에서 올라오는 창, 데스크톱은 가운데 560px 상자).
2. 대상은 **모든 계정**(사용자 질문 → "모든 계정"). 플랫폼 관리자 · 정지된 계정 · 나 자신은 흐리게 보이고 바꿀 수 없다.
3. 창: 이름 · 아이디 찾기(모든 부서, 부서 이름을 함께), 부서 칩(처음은 지금 사람의 부서, "부서 없음" 포함), 역할 칩(전체 · 학생 · 교사 · 임원 · 학부모 · 기타 · 관리자, 수 함께),
   최근에 본 사람(이 관리자의 가장 시작 · 바꾸기 감사 로그에서 최근 5명, 지금 사람 맨 위), 이름 순 30명씩 + [더 보기]. 줄마다 역할 칩 · 반(담임) · 아이디.
4. 바꾸면 같은 쿠키 방식(가장한 관리자 Id 유지)으로 그 사람이 된다. 보던 화면이 그 사람 부서의 화면이면 **같은 주소 그대로**, 아니면 그 부서 홈(부서가 없으면 첫 화면).
5. 바꿀 때마다 가장한 관리자가 지금도 플랫폼 관리자인지 다시 확인하고, 감사 로그 `ImpersonateSwitch`(Detail `from=…;account=…`)를 남긴다. [복귀]는 그대로.
6. 시험 도구(0095)의 상황별 로그인 버튼은 플랫폼 관리자(또는 가장 중)가 누르면 **가장으로** 들어간다 — 들어간 뒤에도 띠의 [사람 바꾸기] · [복귀]가 보인다.

## 구현
`Services/UserSwitchService.cs`(목록 · 바꾸기 · 갈 곳), `Pages/Account/ImpersonateSwitch.cshtml(.cs)` `/account/impersonate/switch`(frag=true 면 창 안 내용만), `wwwroot/js/imp-switch.js`, `_Layout` 띠 버튼, CSS `sw-`. 테스트 `UserSwitchTests`.
