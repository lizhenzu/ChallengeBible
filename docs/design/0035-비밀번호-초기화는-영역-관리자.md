# 0035. 비밀번호 초기화는 영역 관리자가 임시 비밀번호로

- 상태: 확정 (2026-10-22, 사용자와 합의)
- 관련: 0004(D4), R-137, 0034, API · 화면 계약 4-1 · 5-4

## 맥락
아이 계정은 아이디 · 비밀번호 · 이름만 받는다(R-137). 이메일 · 전화가 없으니 자동 "비밀번호 찾기"를 만들 수 없다.
플랫폼 관리자만 초기화하면 요청이 운영자에게 몰린다.

## 결정
1. **영역 관리자**가 자기 영역 소속(승인 · 정지 상태)의 계정 비밀번호를 **임시 비밀번호로 초기화**한다. 플랫폼 관리자도 할 수 있다.
2. 임시 비밀번호는 서버가 만들어 관리자 화면에 **한 번만** 보여 준다. 관리자가 아이에게 직접 전한다.
3. 초기화된 계정은 다음 로그인 때 **새 비밀번호로 바꾸기 전에는 다른 화면을 쓸 수 없다**.
4. 계정은 전역이므로(0004) 다른 부서에 영향을 준다. 그래서 영역 관리자는 다음 계정을 초기화할 수 **없다**:
   - 플랫폼 관리자 계정
   - **다른 영역에서 영역 관리자 역할**을 가진 계정
   - 이 경우는 플랫폼 관리자가 한다.
5. 초기화는 감사 로그에 남긴다(누가, 언제, 어느 영역에서, 어느 계정).

## 결과
- Account 에 `MustChangePassword`(참거짓) 열을 더한다. 초기화 시 참, 새 비밀번호 저장 시 거짓.
- 대상 계정의 다른 영역 소속을 확인해야 하므로(4) 이 처리는 시스템 연결로 실행한다(물리 설계 3-3).
- API: `POST /api/{slug}/admin/members/{id}/reset-password` → `{ "temporaryPassword": "…" }`
