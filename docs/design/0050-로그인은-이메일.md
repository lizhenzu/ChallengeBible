# 0050. 로그인 키는 이메일 — 아이디를 대신한다 (D14 개정)

- 상태: 확정 (2026-10-23, 사용자 결정)
- 관련: D14(만 14세 미만 동의), R-137, 용어집 "계정", 0048(참여 코드)

## 배경
계정 로그인 키가 영어 소문자 · 숫자 4~20자의 "아이디"(`Account.LoginId`)였다. 사용자가 이메일로 관리하기로 했다.

## 결정
1. 로그인 키는 **이메일**이다. 아이디는 없앤다. 컬럼은 `Account.Email`(nvarchar 254, 유일 `UQ_Account_Email`).
2. **모든 사용자**에게 적용한다. 만 14세 미만도 자기 이메일을 직접 입력한다.
3. D14 · R-137 의 "아이디 · 비밀번호 · 이름(또는 별명)"은 **"이메일 · 비밀번호 · 이름(또는 별명)"** 으로 바꾼다. 전화 · 생일 · 주소를 받지 않는 점은 그대로다.
4. 1차에서는 **인증 메일을 보내지 않는다.** 형식(`@` 와 점 포함, 공백 없음, 254자 이하)만 검사한다. 저장 · 비교는 소문자로 한다.
5. 비밀번호를 잊으면 영역 관리자 · 플랫폼 관리자가 초기화한다(기존 방식). 메일 발송 · 인증 · 메일로 비밀번호 찾기는 SMTP 설정 이후 별도 결정이다.

## 결과
- 마이그레이션 `EmailLogin`: 열 이름 변경 + 길이 확장 + 유일 인덱스 이름 변경. 데이터는 지우지 않는다.
- 이미 만든 계정은 `@` 가 없는 옛 아이디로 남아 로그인할 때 쓸 수 없다. 계정이 있으면 `UPDATE app.Account SET Email = '<이메일>' WHERE Email = '<옛 아이디>'` 로 고친다.
- 이메일은 개인정보다. 아이는 보호자 동의(D14)로 받는다. 화면 · 목록에 이메일을 보이는 곳은 소속 관리 · 부서 관리자 목록뿐이며, 같은 영역 관리자에게만 보인다.
- 1차에 이메일 인증이 없어서 남의 이메일로 가입할 수 있다. 인증 전까지 이메일은 "로그인 이름"일 뿐 본인 확인 수단이 아니다.
