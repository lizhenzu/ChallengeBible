# 0020. 이중 격리 — RLS + EF Core 전역 쿼리 필터

- 상태: 확정 (2026-10-21)
- 원래 결정: D20
- 관련: 0007, 0018, R-131, X-23

## 맥락
Pool 방식(0007)에서는 테넌트 조건 하나가 빠지는 실수가 곧 다른 영역 데이터 노출이다.
어느 한 층만 믿으면 그 층의 실수를 막을 방법이 없다.

## 결정
- DB 의 **RLS** 와 앱의 **EF Core 전역 쿼리 필터** 를 **둘 다** 쓴다.
- 저장 시에도 TenantId 는 요청의 테넌트 컨텍스트에서 채우고, 다른 값이면 거절한다.

## 결과
- 한쪽(예: 필터를 끈 쿼리, 원시 SQL)이 실수해도 다른 쪽이 막는다.
- 전역 필터를 끄는 코드(`IgnoreQueryFilters`)는 플랫폼 관리 경로에서만 허용하고 감사 로그를 남긴다.
- **테넌트 격리 테스트**를 필수로 둔다: 다른 영역 ID 로 조회 · 저장을 시도하면 결과는 "없음" 이어야 한다(R-131).
