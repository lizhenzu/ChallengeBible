# 0095. 임시 시험 도구 화면(/test-tools)

- 상태: 확정 (2026-11-14, 사용자 지시 — 선물 시스템 시험용)
- 관련: 0067(플랫폼 관리자 가장), 0090(공유 표 · Identity), 0094 예정(선물 시스템)

## 맥락
선물 시스템을 시험하려면 점수대 · 생일 · 새친구 · 통독 완독 · 가족팀 단계가 고루 있는 가짜 데이터가 필요하다.
SQL 은 `tools/sql/gen-fake-seed.py` 로 만들었지만, 사용자가 쓰는 SQL Studio(sql.site4now.net)는
`sp_set_session_context` · `ALTER SECURITY POLICY` · 시스템 표 · 커서 · OPENJSON 을 막아 부서 격리(RLS)를 넘을 수 없고, PC 를 쓸 수 없는 때가 있다.
사용자는 휴대폰만으로 넣기 · 지우기와 상황별 로그인을 하고, 시험이 끝나면 숨겼다가 필요할 때 다시 열기를 원했다.

## 결정
1. 앱에 임시 화면 `/test-tools` 를 둔다. 설정 `TestTools:Enabled`(appsettings.json)가 false 면 화면 · 메뉴가 없다(404). 숨기기 · 다시 열기 = 이 값을 바꿔 게시.
2. 화면은 플랫폼 관리자와 가짜 계정(이메일 `@fake-seed.test`)만 본다. 그 밖은 404.
3. **가짜 데이터 넣기 · 지우기**는 플랫폼 관리자만(시스템 연결, 시작마다 DB 로 다시 확인). 시험 실행(끝에 되돌림)과 진짜 실행이 있고, 진짜 실행은 확인 글자 `FAKE` 를 써야 한다. 진짜 실행은 감사 로그(`FakeDataCreate` · `FakeDataDelete`)에 남긴다.
   SQL 은 생성기가 만든 `src/ChallengeBible.Web/TestTools/*.sql`(EmbeddedResource)이고, 시스템 연결이 PlatformScope 를 켜므로 SQL 안에서는 격리 설정을 하지 않는다. 저장 여부 · 기준 날짜(한국 날짜)는 매개변수.
   넣기는 플랫폼 관리자(SuperAdmin) 계정만 남기고 모든 계정 · 기록을 지운 뒤 넣는다(진행 문서 "가짜 시험 데이터" 참고).
4. **상황별 로그인**: 부서마다 상황(관리 · 선생님, 점수 · 크레딧, 생일, 통독, 가족팀 · 친구팀) 버튼. 누르면 비밀번호 1234 로 일반 로그인과 같은 확인(`AccountService.LoginAsync`)을 거쳐 그 계정으로 들어간다. 가짜 계정이 아니면 들어가지 않는다. 가짜 계정으로 들어간 뒤에도 이 화면에서 다른 가짜 계정으로 바꿀 수 있다.
5. 상황 목록(`TestToolsService.Scenarios`)은 생성기의 틀과 같아야 한다. 틀을 바꾸면 둘 다 고친다.

## 결과
- 운영 사이트에 "모든 계정을 지우는" 기능이 켜져 있는 동안 위험하다. 실제 사용자가 생기기 전까지만 쓰고, 시험이 끝나면 `TestTools:Enabled = false` 로 숨긴다.
- PC 의 SSMS 로 할 때는 `tools/sql/fake-create.sql` · `fake-delete.sql`(sp_set_session_context 판)을 쓴다.
- 테스트: `TestToolsTests`(숨김 · 권한 · 가짜 계정만 로그인 · 확인 글자 · 앱 SQL 점검).
