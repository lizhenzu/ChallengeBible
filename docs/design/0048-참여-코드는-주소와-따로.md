# 0048. 참여 코드는 주소와 따로 둔다 — 6자, 다시 만들 수 있음

- 상태: 확정 (2026-10-23, 사용자와 합의 — 플랫폼 부서 관리 시안 검토)
- 관련: 0008(주소 경로), 0026(진급 대상 확인), 0045(`/join` 부서 코드로 참여 신청)

## 맥락
0045 는 소속이 없는 사람이 선생님께 받은 **부서 코드**로 참여 신청을 하게 했지만, Tenant 에는 주소(Slug)만 있고 코드를 담을 칸이 없었다.
주소를 코드로 쓰면 아이가 넣기에 길고(`jamsil-kids`), 코드가 밖으로 퍼졌을 때 주소까지 바꿔야 한다.

## 결정
1. Tenant 에 **참여 코드(JoinCode)** 를 둔다. 영어 대문자 · 숫자 **6자**, 모든 영역에서 유일.
   헷갈리는 글자(0 · O · 1 · I)는 만들 때 쓰지 않는다.
2. 영역을 만들 때 서버가 저절로 만든다. **플랫폼 관리자**가 "새 코드로 바꾸기"로 다시 만들 수 있다.
   바꾸면 예전 코드로는 신청할 수 없고, 이미 있는 소속 · 신청은 그대로다.
3. 주소(Slug)는 그대로 주소로만 쓰고, 만든 뒤에는 바꾸지 않는다.
4. 참여 신청(`/join`)과 진급 대상 확인(0026)은 **참여 코드**로 영역을 찾는다. 돌려주는 것은 이름 · 켠 프로그램뿐이다.
5. 정지된 영역의 코드는 "찾을 수 없음"과 같게 답한다.
6. 코드 맞히기를 막기 위해 찾기 요청은 계정당 횟수 제한을 둔다(1분 10회).

## 결과
- 논리 설계 Tenant 에 `JoinCode` 를 더한다(UK, CK 6자 대문자 · 숫자).
- API: `GET /api/join/lookup?code=`, `POST /api/join`, `DELETE /api/join/{membershipId}`(신청 취소),
  `POST /api/platform/tenants/{id}/join-code`(다시 만들기). 진급 확인은 `lookup?code=` 의 code 가 참여 코드다.
- 시안: 부서참여신청 · 소속관리(진급 보내기) · 플랫폼-부서관리 단독 시안.
