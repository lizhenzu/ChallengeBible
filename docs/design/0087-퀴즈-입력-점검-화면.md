# 0087. 퀴즈 입력 점검: 말씀 점검과 같은 달력으로 본다

- 상태: **확정 · 구현** (2026-11-07, 사용자, R-217)
- 확정 시안: `시안/quiz-check.html` (`quiz-check-1.png` · `quiz-check-2.png`)
- 주소: `/platform/content/quiz/check?month=yyyy-MM&date=yyyy-MM-dd`, 플랫폼 관리자만. 공용 콘텐츠의 퀴즈 화면 "입력 점검"에서 들어간다.

## 결정(사용자)
1. 점 4개는 **배경 · 문제 · 4지선다 · 힌트** 순서다.
2. 4지선다는 보기 4개가 모두 차 있고 정답이 정해져 있어야 입력된 것으로 본다. 저장 규칙은 보기 2 ~ 3개도 받지만 점검에서는 없음으로 센다.
3. 주관식은 맞는 답이 있으면 입력된 것으로 본다. 빠지면 "4지선다 없음" 칩으로 함께 센다. 그날 칸에서는 "주관식 답"으로 표시한다.

## 구현 때 정한 것
- **힌트**: 따로 된 칸이 없다. 퀴즈 화면의 "힌트 보기"가 해설(`Explanation`)을 보여 주므로 그 칸으로 판정한다.
- **배경 · 힌트**: 저장할 때는 비워도 되지만 사용자가 점검 항목으로 정했으므로 비어 있으면 빠진 곳으로 센다.
- **공용 틀**: 말씀 점검(ADR 0086)의 페이지 · 스크립트를 `ContentCheck` · `content-check.js` 로 바꿔 말씀 · 퀴즈가 함께 쓴다. 판정은 각각 순수 함수 `WordCheck.Day` · `QuizCheck.Day` 다.

## 결과
- **실DB:** 데이터베이스 변경 없음(읽기만). 게시만 하면 된다.
- 테스트: `WordCheckTests`(퀴즈 판정 경계값 · 한 달 조회 · 권한 · 실제 화면을 Edge headless 에서). Edge 실행은 `Support/EdgePage` 로 옮겼다. Edge 가 없는 환경에서는 화면 시험만 건너뛴다.
