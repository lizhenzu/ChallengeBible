# 0026. 진급 절차 — 이전 영역이 내보내고, 새 영역이 승인할 때 삭제

- 상태: 확정 (2026-10-22, 사용자와 합의)
- 보완 대상: 0016(D16), 0022(D22)
- 관련: R-139, 04 문서 2-4 "소속 관리 — 진급 처리"

## 맥락
04 문서는 영역 관리자 화면에 "진급 처리"를 둔다. 그런데 영역은 완전히 격리되어 있어(0003, 0007)
이전 영역(유년부) 관리자는 새 영역(초등부)을 볼 수도 바꿀 수도 없다.
진급은 두 영역에 걸친 유일한 업무 흐름이라, 누가 무엇을 하는지 정해야 했다.

## 결정
1. **이전 영역 관리자가 내보낸다.** 소속 관리에서 참여자를 골라 "진급 처리"를 누르고 **새 영역 코드**를 입력한다.
2. 새 영역에 그 계정의 **"진급 대기" 소속 신청**이 생긴다.
3. **새 영역 관리자가 승인**하면(동의 확인 포함, 0014) 그때 이전 영역의 데이터를 **완전 삭제**한다(범위는 0022).
4. 승인 전까지 이전 영역 소속은 그대로다. 아이는 이전 영역에서 계속 미션을 할 수 있다.
5. 새 영역 관리자가 **거절**하면 진급은 취소되고 아무것도 지워지지 않는다.

## 결과
- 아이가 어느 영역에도 소속이 없는 틈이 생기지 않는다.
- 이전 영역 관리자가 아는 것은 "입력한 영역 코드"뿐이다. 새 영역의 이름 외 정보는 보여 주지 않는다
  (코드 오타를 막기 위한 영역 이름 확인 정도만 허용 — API · 화면 계약에서 확정).
- 영역 간 요청인 "진급 요청(PromotionRequest)" 은 두 영역에 걸친 기록이다.
  어느 쪽 TenantId 로 두고 RLS 를 어떻게 통과할지는 도메인 모델 · 물리 설계에서 정한다.
- 승인 처리(새 소속 활성화 + 이전 영역 삭제)는 한 트랜잭션으로 묶는다.
