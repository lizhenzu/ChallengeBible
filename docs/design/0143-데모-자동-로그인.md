# 0143 · 영상 촬영용 데모 자동 로그인 (2026-11-28, 임시 기능)

## 결정
- 홍보 · 사용법 영상 촬영용으로, 비밀번호 없이 `GET /demo/admin?key=…`(데모 관리자 → 관리자 메인) · `GET /demo/user?key=…`(데모 학생 → 미션홈)으로 로그인한다.
- 데모 데이터는 **데모 전용 영역 `demo-school`**(실제 영역과 완전 격리, 영역 = 테넌트)에만 둔다. 주소가 `/demo/…` 로그인과 겹치지 않도록 슬러그는 demo 가 아니다. 가입 목록에는 안 나온다(JoinListed = false).
- 로그인은 기존 쿠키 인증 그대로(`CurrentUser.SignInAsync`). 권한 우회 없음 — 데모 계정 자체의 권한(부서 관리자 / 학생)으로 동작. 다른 계정으로 로그인돼 있으면 먼저 로그아웃.

## 보안
- 설정 `DemoLogin { Enabled, Key, ExpiresAt }`(기본 꺼짐). 꺼짐 · **기한 없음/지남** · 키 없음/틀림 · 알 수 없는 종류 → 모두 **404**(존재를 숨김). 기한이 없는 상태로는 열리지 않는다.
- 키는 소스에 두지 않는다 — 환경변수 `DemoLogin__Key`(또는 서버 설정)에서만 읽는다. 비교는 고정 시간 비교. 응답은 `Cache-Control: no-store`.
- 데모 계정(`demo_admin` · `demo_user` …, 이메일 `@demo.invalid`)의 비밀번호는 아무도 모르는 64바이트 랜덤 값 → 데모 링크로만 로그인.
- 로그인마다 감사 기록(AuditLog `DemoLogin`: 일시 · IP · 계정)과 서버 로그(키는 기록 안 함). 틀린 키는 IP 만 서버 로그에 남긴다.

## 샘플 데이터(첫 데모 로그인 때 한 번만 만든다 — 여러 번 불러도 중복 없음)
- 데모 관리자 1 · 가상 학생 10명(김하늘 = 데모 일반 사용자, 이바다, 박사랑, 최은총, 정믿음, 한소망, 오기쁨, 서평화, 윤다솜, 강보람) · 학부모 1.
- 최근 14일 말씀 · 기도 · 퀴즈 · 암송 기록을 사람마다 다르게(완료 · 일부 · 아직). 데모 학생은 오늘 말씀만 한 상태(진행 중).
- 가족팀(하늘이네 가족) · 친구팀(바다와 사랑) 각 1개.
- 말씀 · 퀴즈 · 기도 · 암송 **콘텐츠는 플랫폼 공용 콘텐츠**를 그대로 쓴다(데모 전용 콘텐츠는 없음).

## 켜기 / 끄기 / 삭제
- 켜기(서버 환경변수): `DemoLogin__Enabled=true` · `DemoLogin__Key=<긴 랜덤 문자열>` · `DemoLogin__ExpiresAt=2026-12-15T23:59:00+09:00`. 주소 예: `https://사이트/demo/user?key=<키>`.
- **끄기**: `DemoLogin__Enabled=false`(또는 기한 지남, 또는 키 비움) → 두 주소 모두 404. 데이터는 남는다.
- **완전 삭제**: ① SQL `TestTools/demo-remove.sql` 실행(영역 · 기록 · 데모 계정 삭제, 처음엔 미리보기) ② 코드 삭제: `Services/DemoSeedService.cs` · `Services/DemoLoginService.cs` · `Api/DemoLoginApi.cs` · `tests/.../DemoLoginTests.cs` · `Program.cs` 의 DemoLogin 두 줄(`AddScoped<DemoSeedService>`/`AddScoped<DemoLoginService>`, `MapDemoLogin`) · `appsettings.json` 의 DemoLogin 블록 · `TestTools/demo-remove.sql`.
