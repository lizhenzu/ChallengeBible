# 0034. 화면은 서버 렌더링(Razor Pages), 버튼 동작은 JSON API

- 상태: 확정 (2026-10-22, 기술 결정)
- 관련: 0011(D11), 0008(D8), X-13, X-14, X-20

## 맥락
기술은 ASP.NET Core + PWA 로 정해졌지만(0011) 화면을 만드는 방식은 정하지 않았다.
선택지: (1) 서버 렌더링(Razor Pages) (2) 별도 SPA(React 등) + API (3) Blazor.
호스팅은 공유 호스팅(SmarterASP)이고, 화면은 휴대폰 우선의 단순한 카드 · 버튼 위주다.

## 결정
1. **화면은 Razor Pages 로 서버에서 그린다.** 화면마다 전용 ViewModel 을 쓴다(X-13: ViewBag · TempData 금지).
2. **버튼 동작**(미션 저장, 퀴즈 제출, 읽음 표시 등)은 **JSON API** 로 부르고, 화면 일부만 갱신한다(작은 자바스크립트, 프레임워크 없음).
3. PWA: 매니페스트 + 서비스 워커(정적 파일 캐시, 홈 화면 설치). 오프라인 미션 저장은 하지 않는다.
4. 인증: 웹은 **쿠키 인증**(클레임에 AccountId — X-20). 외부 연동 API 는 2차에 영역별 API 키.
5. 모든 서버 코드는 단일 서비스 계층 + DI + async(X-14). 화면과 API 는 같은 서비스를 부른다.

## 결과
- 빌드 도구 · 프런트엔드 프레임워크 없이 한 프로젝트로 배포한다(공유 호스팅에 맞음).
- 첫 화면이 빠르고, 아이 휴대폰(저사양)에서도 가볍다.
- API 계약은 버튼 동작과 외부 연동에 필요한 만큼만 둔다. 화면을 그리는 데이터는 API 가 아니라 ViewModel 이다.
