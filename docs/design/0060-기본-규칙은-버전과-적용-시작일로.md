# 0060. 기본 규칙은 버전과 적용 시작일로 저장한다

- 상태: 확정 (2026-10-24, 사용자와 합의)
- 관련: CLAUDE.md "점수 규칙 값은 코드에 쓰지 않고 RuleSet 에서 읽는다", 0032(미션마다 켜진 항목 하나 이상), 0052(암송 주 번호), 확정 시안 플랫폼-기본규칙

## 맥락
점수 · 수행 규칙(RuleSet)은 지금까지 코드 기본값 하나뿐이었다. 플랫폼 관리자가 화면에서 값을 바꿀 수 있어야 하고,
하루 중간에 점수가 바뀌거나 이미 쌓인 점수가 흔들리면 안 된다. 물리 설계의 `PlatformRuleSetVersion` 에는 적용 시작일이 없었다.

## 결정
1. 규칙은 **버전**으로만 바꾼다. 저장할 때마다 새 버전(번호 +1), 값은 RuleSet 전체 JSON.
2. 버전마다 **적용 시작일**(`EffectiveFrom`, date)을 둔다. 고를 수 있는 날은 **내일** 또는 **다음 주 시작일**뿐이다(오늘 중간에 바뀌지 않게).
3. 어떤 날의 규칙 = 적용 시작일이 그날 이전인 버전 가운데 **번호가 가장 큰 것**(나중 결정이 이긴다). 미션은 **미션 날짜** 기준으로 고른다.
4. 표가 비어 있으면 코드 기본값(`RuleSet.Default`)이 v1 이다. 첫 저장이 v2.
5. 이미 쌓인 점수는 수행 기록 · 원장에 그때 점수로 남아 있으므로 바뀌지 않는다(R-63 · R-64). 이미 도달한 축하 단계도 취소하지 않는다.
6. 1차 범위(사용자 확정):
   - 주 시작 요일은 **바꾸지 않는다**(암송 주 번호 0052 · 이번 주 점수가 어긋난다). 화면에는 보기만.
   - 미션 항목 6개는 고정. 켜기 · 이름(1~20자) · 점수(0~10점)만 바꾼다. 미션마다 하나는 켜져 있어야 한다(0032).
   - 퀴즈 도전 1~3번, 인정 기간 1~7일, 축하 단계는 서로 다른 양수 하나 이상, 가족 단계는 있는 줄만 고친다, 기능 스위치는 값만 저장(화면은 2차).
7. 저장은 플랫폼 관리자만(시스템 연결 + 시작마다 DB 로 다시 확인). 저장 사실과 바뀐 점은 AuditLog(`RuleSetSaved`)에 남긴다.
8. 부서별 규칙(`TenantRuleSetVersion`)은 2차.

## 결과
- 표 `app.PlatformRuleSetVersion` 에 `EffectiveFrom date NOT NULL` 을 더해 만든다(마이그레이션 `PlatformRuleSet`, 실DB 는 `tools/sql/migrate-platformruleset.sql`). 플랫폼 표라 RLS 없음.
- `RuleService.ForDateAsync(date)` 가 규칙을 읽는다(잠깐 기억, 저장하면 지움). `MissionService` 는 요청 처음에 미션 날짜의 규칙을 읽는다.
- 화면: `/platform/rules` — "바뀐 점 보기"로 서버가 바뀐 값 · 오류를 보여 주고, 확인한 뒤 "새 버전으로 저장".
