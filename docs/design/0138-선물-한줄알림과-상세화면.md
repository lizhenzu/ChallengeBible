# ADR 0138 — 「오늘의 말씀」 아래 한 줄 선물 알림 + 「선물 대상자와 상태」 상세 화면

- 날짜: 2026-11-23
- 상태: 확정 (사용자 "B안으로")
- 시안: `docs/design/시안/선물알림-오늘의말씀아래-3안.html` / `.png`
- 앞선 결정: ADR 0134(홈 선물 카드), R-297(가격 없음 · 받은 지 30일)

## 배경

홈의 「선물 대상자와 상태」 카드는 사람마다 한 칸씩(이름 · 개인 배지 · 선물 이름 · 3단계 눈금)이었다.
「오늘의 말씀」 아래에 두니 카드가 세로로 길어져 말씀 카드가 밀렸다.
사용자 요청: **한 줄짜리 알림 카드로 「오늘의 말씀」 밑에 두고, 누르면 새 페이지에서 첨부 이미지처럼 자세히.**

## 결정 (B안)

### 1. 홈은 한 줄만

- 부품: `Pages/Shared/_GiftAlert.cshtml` (새 파일). 클래스 `vb-galert`.
- 내용: 🎁 타일 + 「선물 N명」 + 「받았어요 N명 · 준비 중 N명」 + 오른쪽 미니 3칸 눈금 + `›`.
- **홈에서는 사람 이름 · 선물 이름을 꺼내지 않는다** — 한 줄을 유지해야 「오늘의 말씀」이 자리를 지킨다.
- 자리: 「오늘의 말씀」 카드 바로 아래, 가족팀 초대 배너 위. 첫 화면(`/`)·부서 홈(`/{slug}`) 둘 다 같은 부품.
- 대상이 없으면(Total 0) 카드를 **아예 그리지 않는다**. 손님에게는 로그인 안내 한 줄.
- 기존 `_GiftTargetCard.cshtml` 는 삭제(쓰는 곳 없음).

### 2. 상세 화면 `/{slug}/gift-status`

- `Pages/Mission/GiftStatus.cshtml(.cs)` — 새 화면. 모델 `GiftStatusModel`.
- 열 조건: `tenant.IsApproved && !tenant.IsLobby`. 아니면 404(기존 `TargetBoardAsync` 규칙 그대로).
- 구성: 「홈으로」 → 제목/부제 → **진행 스트립**(골랐어요 → 샀어요 → 줬어요) → 사람별 카드 목록 → 30일 안내.
- 사람별 카드(`vb-gs-row`): 56px 사진 타일 · 이름(19px) · 개인 배지 + 선물 이름 · 3칸 눈금 · 상태 알약.
  받은 사람은 옅은 초록 바탕(`.done`) + 초록 「받았어요」 알약(`.st.s3`).
- 데이터: `GiftOrderService.TargetBoardAsync(200, ct)` — 홈(3명)과 같은 쿼리, 개수만 다르다.
- 넘치는 인원은 아래 「선물 대상자 N명 전체 보기 ›」 → 기존 `/{slug}/gift-board`(R-297 전체 명단).

### 3. 값

- `GiftTargetCardVm`(기존) 을 그대로 쓴다. 링크만 `MoreHref`(전체 명단) 대신 `vb-galert` 가 `/{slug}/gift-status` 로 간다.
- 점수 · 금액은 홈도 상세도 넣지 않는다(R-297).

## CSS

- `landing.css` 끝에 추가. 접두사 `vb-galert` · `vb-gs-` 로 좁혀 `site.css` 의 일반 이름(`.in` · `.stg` · `.sum`)과 부딪히지 않게 한다(ADR 0136 의 `rb-` 교훈).

## 테스트

- `GiftOrderTests`: 홈은 `vb-galert` + `href="/kids/gift-status"` + 이름 없음, 상세는 `vb-gs-row` + 이름 · 선물 이름 · 3단계 + 상태 클래스(`st s2` / `st s3` / `vb-gs-row done`).
- 대상 없음: 홈에 `vb-galert` 없음, 상세는 「아직 선물 대상자가 없어요」, 손님은 로그인 안내.

## 남는 것

- `/{slug}/gift-board`(전체 명단, R-297)는 그대로 둔다. 상세의 「전체 보기」가 그 화면으로 이어진다.
- 게시는 사용자가 GitHub Actions "Publish to SmarterASP" 로 직접 한다.
