# 0049. 솔루션 구조 — 도메인 · 인프라 · 웹 · 테스트 네 프로젝트

- 상태: 확정 (2026-10-23, 1차 구현 시작 — 기술 결정)
- 관련: 0011(.NET), 0020(이중 격리), 0034(Razor Pages + JSON API), 0037(코드 이름 ChallengeBible), 물리 설계 3-3 · 5절

## 결정
1. 솔루션 `ChallengeBible.sln`, SDK 는 `global.json` 으로 **.NET 9**(9.0.318, 같은 대 버전 안 최신 패치)에 고정한다.
2. 프로젝트 네 개
   | 프로젝트 | 내용 | 참조 |
   |---|---|---|
   | `src/ChallengeBible.Domain` | 규칙 · 값 · 계산(날짜, 인정 기간, 시즌, 점수, 퀴즈, 단계). DB · 웹을 모른다 | 없음 |
   | `src/ChallengeBible.Infrastructure` | EF Core(SQL Server), DbContext, 세션 값 넣기(연결 가로채기), 전역 필터, 시스템 연결 팩토리, 마이그레이션 | Domain |
   | `src/ChallengeBible.Web` | Razor Pages 화면 · JSON API · 쿠키 인증 · 서비스 계층 · PWA 정적 파일 | Domain, Infrastructure |
   | `tests/ChallengeBible.Tests` | xUnit. 업무 규칙 테스트는 이름에 R-번호를 붙인다. 격리 · 아키텍처 테스트 | 모두 |
3. 업무 규칙 값은 Domain 의 `RuleSet` 으로만 읽는다. 1차 기본값은 `RuleSet.Default`(03 문서 기본값 표와 같음)이고, 저장 후에는 DB 의 규칙 버전에서 읽는다.
4. "오늘"은 `TenantClock`(TimeProvider 주입)만 계산한다. 테스트는 가짜 시각을 넣는다.
5. 시스템 연결 팩토리는 Infrastructure 안의 한 클래스로만 만들고, Web 의 일반 요청 경로가 참조하지 않는지 아키텍처 테스트로 검사한다(물리 설계 3-3).

## 결과
- 공유 호스팅(SmarterASP)에는 Web 하나를 게시한다(0034 결과와 같음).
- 개발 DB 는 SQL Server 2019 이상이 필요하다(RLS · `sp_set_session_context` 읽기 전용). 이 PC 의 LocalDB 는 2014 라 쓸 수 없다.
