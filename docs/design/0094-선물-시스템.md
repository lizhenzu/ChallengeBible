# 0094. 선물 시스템(선물 목록 · 개인 · 새친구 · 초대 · 생일 · 완독 · 가족팀 · 친구팀)

- 상태: 확정 (2026-11-14, 사용자가 질문으로 하나씩 정함 — 진행 문서 "선물 시스템 결정"을 옮김)
- 고치는 것: 0093 의 가족팀 · 친구팀 시상 금액(단계마다 기본 5,000원 → 아래 "가족팀 · 친구팀" 공통 금액, 부서는 단계별 최대 금액만), 0092 시상 기록(전달 완료 때 기록)
- 관련: 0090(공유 표), 0091 · 0092(시상 기준 · 기록), 0093(통합 · 친구팀 · 새친구), R-274(선물 이미지 폴더), 업무 규칙 R-276 ~ R-299
- 유년부 원본(읽기 전용): 상품 `AwardItem`, 가격 규칙 `Services/GiftCatalog/GiftPriceRule.cs`, 주문 `StudentPointGiftOrder` · `BibleGiftOrder`(+Log) · 생일 `PresentItemPick`, 관리 `Services/GiftAdmin/GiftAdminFacade.cs`, 상품 관리 `Controllers/PresentController.cs`

## 맥락
유년부 사이트의 선물 기능(선물 등록 · 점수 도달 시 선물 링크 · 신청 · 구매 · 전달 · 이력 · 총비용)을 ChallengeBible 로 옮긴다(0093).
옮기면서 "모든 부서 공통 틀 + 부서 설정"으로 다시 만들고, 유년부에 따로 있던 주문 표들을 하나의 흐름으로 묶는다.
금액 · 크레딧 · 기간 같은 값은 코드에 쓰지 않고 규칙(플랫폼 기본값)과 부서 설정에서 읽는다(CLAUDE.md).

## 결정

### A. 선물 목록(공통 · 부서)
1. 유년부 상품은 **공통 선물**이 된다. **상품 번호 그대로**, 이미지 `/images/AwardItem/{번호}.jpg`(R-274).
2. 부서는 공통 선물 중 안 맞는 것을 **숨기고**, **자기 부서 선물을 더한다.** 기본은 공통 전체가 보인다.
3. 부서 선물을 **"공통에 올리기"** 하면 **승인 없이 바로** 공통이 된다.
4. 공통에 올린 선물은 **올린 부서와 플랫폼 관리자 둘 다** 고칠 수 있다(모든 부서에 반영).
5. 상품 번호는 **번호줄 하나**(공통 · 부서 구분 없음), 유년부 마지막 번호 다음부터.
6. 상품 등록: 사진은 **정사각형으로 잘라 JPG**(없으면 기본 그림), **구매 링크는 쿠팡(`coupang.com`)만, 반드시**.
7. 유년부 상품은 **모두 옮긴다.** 쿠팡 링크가 없거나 쿠팡이 아닌 것, 유년부에서 숨긴 것은 **"삭제 대상"** 목록에 따로 두고 아이에게 보이지 않는다. 관리자가 고쳐 살리거나, **삭제 = 상품 + 서버 이미지 삭제**.
8. 삭제할 때 챌린지에서 **고른 기록이 있으면 "목록에서 내리기"**(이름 · 사진 · 금액은 이력 · 총비용에 남음), 없으면 완전 삭제.

### B. 도전 성경말씀 개인 선물(학생만)
1. 개인 선물은 **순위 · 가족팀 합산과 따로** 센다. 미션 기록은 지우지 않고 **"선물에 쓴 포인트"를 따로 기록**한다.
2. 크레딧: 그해 **처음 100점 = 5,000**(1년에 한 번), 그 뒤 **100점마다 1,000**.
3. 신청하면 선물값만큼 쓰고, **남은 100점 단위는 100점당 1,000 크레딧으로 남기고**, 100점 미만 자투리는 지운다.
4. **해가 바뀌면 0부터.** 12월에 "올해 안에 신청하세요" 안내.
5. **상한**: 부서 설정, 공통 기본 **30,000 크레딧**. 닿으면 더 쌓이지 않고 안내한다.
6. **크레딧 → 금액**: 부서가 **1,000 단위 표**로 정한다(빈칸 = 1크레딧 1원).
7. 취소: **구매 완료 전에는 본인 취소 = 되돌림.** 구매 완료 뒤에는 관리자만 되돌린다. 해가 바뀐 뒤 취소는 지운 포인트를 되살리지 않는다.
8. **학생만** 크레딧을 받는다. 선생님 · 학부모 · 기타는 **100점마다 박수**(선물 없음).
9. 본인 알림: 100점 단위를 새로 넘을 때 **창 한 번** + 미션 홈 카드("내 크레딧 · 선물 고르기").
10. 고르기 화면: 고를 수 있는 것 + 비싼 것은 흐리게("○점 더 모으면"), **가격(원)은 아이에게 숨긴다.**

### C. 새친구 · 초대 선물
1. 공통 규칙, 금액은 부서가 **새친구 · 초대 각각** 범위로 정한다(기본 1,000 ~ 15,000원).
2. 새친구 **4주 관리 완료**(0093 출석 8) 때 생긴다. 초대 선물은 새친구에 **"누가 데려옴"이 등록**된 경우에만 데려온 학생에게.
3. 관리자 화면의 **선물 링크**를 선생님이 부모님께 보내 **로그인 없이** 고른다. 기한 없음, 구매 완료 전에는 바꿀 수 있고, 링크를 새로 만들면 옛 링크는 막힌다. 명부 연결은 하지 않는다.

### D. 생일 선물(학생만)
1. 공통 규칙, 기본 1,000 ~ 5,000원(부서 설정). 생일은 **명부 생일**.
2. 계정이 있으면 미션 홈 "🎂 선물 고르기" 카드, 그리고 모든 생일 학생에게 관리자 **선물 링크**. 어느 쪽으로 골라도 **한 건**.
3. 고르는 기간 **생일 30일 전 ~ 7일 전**, 한 해 한 번. 놓치면 관리자 **"다시 열기"(7일)**. 관리자 **건너뛰기**(되돌릴 수 있음).

### E. 성경통독 완독 선물(학생만)
1. 어른은 완독 박수만. 학생은 **회차별 표**: 공통 1독 10,000 · 2독 15,000 · 3독부터 20,000원, 부서가 따로 정할 수 있다(표에 없는 회차는 마지막 줄).
2. 비용 부서 = **완독한 때의 소속 부서**. 기한 **완독 후 30일**, 놓치면 "다시 열기"(7일). 회차마다 하나.

### F. 가족팀 · 친구팀 선물(0093 고침)
1. 단계는 그대로 1,000점마다(1,000 ~ 10,000), 부서가 단계별로 시상 여부를 정한다(0093).
2. **공통 금액**: 가족 1,000점 1만 · 2,000점 2만 · **3,000점부터 3만(최대)**. 친구팀은 **그 절반을 두 사람이 각각**(자동). 부서는 단계별 **최대 금액만** 정한다.
3. 가족팀은 **선물 하나를 팀의 누구나** 고르고, 친구팀은 각자 고른다. 기한 **달성 후 30일** + "다시 열기"(7일).
4. 관리자 "선물 줬어요"는 구매 완료 → 전달 완료로 바꾸는 것이고, **전달 완료 때 시상 기록(0092)을 남기고 팀을 잠근다.**

### G. 관리 · 운영
1. 구매 · 전달 처리는 **부서 관리자만**.
2. **총비용**(구매 완료 금액 합): 부서 관리자 = 자기 부서, 플랫폼 관리자 = 모든 부서. 기간 · 시상 종류별, 엑셀로 받기.
3. **이력**: 선물 한 건마다 모든 동작을 시간순으로(고름 · 바꿈 · 취소 · 구매 · 전달 · 되돌리기 · 다시 열기 · 건너뛰기, 누가).
4. **새해 초기화**: ~~플랫폼 관리자 버튼, 끝나지 않은 선물이 있으면 막음~~ → **새해(1월 1일, 부서 날짜)가 되면 시스템이 무조건 · 저절로 초기화한다**(정한 것 5). 시상 기록은 "지난해 기록"으로 보관하고 화면은 비운다(지난해 총비용 · 이력은 볼 수 있음). 미션 · 출석 · 통독 기록은 그대로.
5. 유년부의 지난 선물 기록은 **옮기지 않는다.**
6. **부서 카드**("누가 선물 받는지"): 미션 홈 **오늘 미션 아래 · 랭킹 위**, 3명 + 더 보기. 달성 → 고른 선물(사진 · 이름) → 관리자 "전달 완료"까지 보인다. 개인 · 새친구 · 초대 · 생일(생일 주) · 완독 · 가족 · 친구 모두.

### H. 공통 흐름(설계 원칙)
1. 선물 한 건의 상태: **생김(고를 수 있음) → 고름 → 구매 완료 → 전달 완료**, 옆길로 **취소 · 건너뛰기 · 기한 지남 → 다시 열기**. 종류(개인 · 새친구 · 초대 · 생일 · 완독 · 가족 · 친구)가 달라도 같은 흐름 · 같은 이력 표를 쓴다.
2. 금액 · 크레딧 · 기간 · 상한의 **공통 기본값은 플랫폼 규칙**에, 부서 값은 부서 설정에 둔다. 코드에 숫자를 쓰지 않는다.
3. 고른 순간의 상품 이름 · 사진 · 금액을 선물 건에 함께 남긴다(상품이 바뀌거나 내려가도 이력 · 총비용이 그대로).

## 개발 순서
1. 이 ADR + 업무 규칙 R-276 ~ (이 문서)
2. 데이터 설계: 상품 · 부서 숨김 · 선물 건 · 이력 표 + 유년부 상품 이관 SQL(삭제 대상 표시)
3. 플랫폼 관리자 상품 관리(등록 · 수정 · 사진 자르기 · 쿠팡 링크 · 삭제 대상)
4. 부서 관리자 설정(공통 숨기기 · 부서 선물 · 공통에 올리기 · 금액 · 크레딧 표 · 상한)
5. 선물 고르기(개인 → 가족 · 친구 → 생일 · 새친구 · 초대 → 완독, 로그인 없는 링크 포함)
6. 구매 · 전달 관리 + 이력 + 부서 카드
7. 총비용 + 새해 초기화

## 정한 것(설계 질문, 2026-11-14)
1. 개인 선물의 점수는 **그해 1월 1일부터** 센다(시즌 시작일과 상관없음, R-282 "해마다 0부터"와 같은 기준). (질문 16 → ①)
2. **아이에게는 점수만** 보인다: 선물마다 "필요한 점수"와 모자라면 "○점 더 모으면". **크레딧은 관리자 화면에만.** 선물의 필요 크레딧 = 부서 크레딧 → 금액 표로 가격을 바꾼 값, 필요 점수 = 그 크레딧을 B-2 규칙으로 되돌린 점수(처음 5,000 = 100점, 그 뒤 1,000 = 100점). (질문 17 → ②)
3. 로그인 없는 선물 링크는 **추측할 수 없는 긴 무작위 주소**(32자)만으로 지킨다. 기한 없음, 구매 완료 전까지 몇 번이든 바꾸고 뒤에는 "준비 중이에요"만, 새로 만들면 옛 링크 막힘, 같은 접속 주소가 짧은 시간에 여러 링크를 열면 잠시 막음, 화면에는 아이 이름 · 선물 종류만(연락처 · 생일 안 보임). (질문 18 → ①)
4. 선물은 종류와 상관없이 **한 장부(`app.Gift`)**에 모두 적는다. (질문 19 → ①)
5. **새해가 되면 시스템이 무조건 초기화한다.** 시상 기록(`DM2_TeamAward`)은 지난해 기록으로 옮기고 비워, 같은 팀이 새해에 같은 단계를 넘으면 다시 받는다. **끝나지 않은 선물(고를 수 있음 · 고름 · 구매 완료)도 모두 닫는다** — 남은 것은 관리자가 오프라인으로 따로 준다. 관리자 버튼 · 막기는 없다. (질문 20 · 21, 사용자 "강제 초기화, 시스템은 무조건 초기화")
