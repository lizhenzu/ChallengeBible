# 0067. 플랫폼 관리자 "가장"(대리 접속)

- 상태: **확정** (2026-10-26, 사용자와 하나씩 정함 · 시안 확정 "진행")
- 관련: API · 화면 계약 `/platform/enter/{slug}`(2차 "대리 접속" 자리), AuditLog, 0035(계정 찾기), D20(격리)

## 맥락
플랫폼 관리자가 부서 관리자 · 교사 · 보호자 · 참여자 화면을 그 사람과 똑같이 써 보며 테스트하고 싶다.

## 결정(사용자, 2026-10-26)
1. **가장 = 그 계정으로 로그인한 것과 같다.** 역할 · 부서 · 격리(RLS)도 그 계정 그대로. 플랫폼 관리자 권한은 쓰지 않는다.
2. **저장은 된다**(미션 · 승인 등 실제 반영). 대신 화면 맨 위에 **"가장 중" 띠**가 늘 보이고, 가장 중에 남는 감사 로그에는 **가장한 플랫폼 관리자**를 함께 적는다.
3. **대상**: 플랫폼 관리자를 뺀 모든 계정(부서 관리자 · 교사 · 보호자 · 참여자 · 소속 없는 계정). 정지된 계정은 안 됨.
4. **시작**: 플랫폼 > 계정 찾기에서 계정을 고르고 [이 계정으로 들어가기] — 확인 한 번.
5. **끝**: 띠의 **[복귀]** 를 누를 때만(시간 제한 없음). 로그아웃하면 둘 다 끝.

## 설계
- 로그인 쿠키에 대상 계정으로 다시 로그인하면서 `ImpersonatorId`(플랫폼 관리자 계정 Id) 값을 더한다. 띠 · 복귀 버튼은 이 값이 있을 때만.
- **[복귀]**: `POST /account/impersonate/stop` — 쿠키의 `ImpersonatorId` 가 지금도 활성 플랫폼 관리자인지 다시 확인한 뒤 그 계정으로 로그인을 바꾸고 계정 찾기 화면으로.
- 시작 · 복귀는 감사 로그 `ImpersonateStart` · `ImpersonateStop`(대상 계정 Id).
- 가장 중 쓰는 감사 로그에 `ImpersonatorAccountId`(새 열, NULL 가능)를 채운다 → 실DB 마이그레이션 SQL 필요.
- **가장 중 막는 것**: 비밀번호 바꾸기 · 이름 바꾸기(내 계정), 다시 가장하기(겹쳐 가장 금지).
- 미션 기록 · 점수 표에는 가장 여부를 따로 적지 않는다(기간은 감사 로그의 시작 · 복귀로 안다).

## 진행
시안(계정 찾기 버튼 · 확인 · 가장 중 띠 · 복귀) → 확정 → 구현 + 테스트(시작 · 복귀 · 플랫폼 관리자 대상 금지 · 막힌 기능 · 감사 로그) → 실DB SQL → 게시.
