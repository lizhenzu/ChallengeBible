# 0120 예전 유년부 계정 · 명부 이관(SQL)

- 날짜: 2026-11-20 · 상태: 확정(사용자 답 1 · 1 · 2 · 1 · 1 · 1, "SuperAdmin 은 가져 오지마")

## 결정(사용자 답)
- 범위: **계정 + 역할 + 명부(이름 · 생일 · 전화) + 반 배정**. 출석 · 미션 · 통독 · 선물 기록은 옮기지 않는다(필요하면 나중에).
- 예전 DB 는 PC 의 SSMS 로 읽기만 한다. 새 DB 는 사이트 [SQL 실행] 화면(시험 실행 → 저장).
- 새 사이트에 **같은 이메일(없으면 같은 아이디)** 계정이 있으면 **예전 것으로 덮어쓴다**: 비밀번호 · 이름 · 전화. 아이디 · 이메일 · 새 사이트 기록은 그대로.
- 권한(Admin · Moderator)은 옮기지 않는다 — 모두 Basic. 부서 관리자는 새 "부서 관리자 규칙"대로.
- **SuperAdmin 계정은 아예 가져오지 않는다**(그 명부 줄 · 반 배정도).
- 새 사이트의 **관리자(Admin · SuperAdmin) 계정은 절대 바꾸지 않는다**(R-315) — 같은 이메일이어도 건너뛴다. SQL 화면도 관리자가 바뀌면 되돌린다.
- 유년부의 **계정 없는 명부 줄 · 반 배정은 비우고** 예전 것으로 채운다(명단 올리기 R-301 · R-302 와 같다). 고른 · 산 · 준 선물이 있는 줄은 남긴다(R-322).
- 반: 예전 `ClassMaster`(쓰는 것) 이름으로 만들고, `ClassInfo_2026` 학생 · `ClassTeacherMap_2026` 담임 · 부담임을 넣는다. ClassMaster 에 없는 학년 · 반은 "N학년 M반".

## 설계
- `tools/sql/yuyunbu-export.sql`(예전 DB, 읽기만): 실행하면 결과 칸(s) 한 줄 = 새 DB 에 넣을 SQL 한 줄. 자료(@U 계정 · @P 명부 · @C 반 · @M 반 배정) + 넣기 본문.
  - 만드는 법: `python3 tools/sql/yuyunbu/build.py` — 넣기 본문은 `tools/sql/yuyunbu/import-body.sql`.
  - 비밀번호는 같은 ASP.NET Identity 해시라 그대로 옮기면 **예전 비밀번호로 로그인**된다.
  - 역할: 사람마다 예전 `DeptRoleUserAssoc` 한 줄(T1099 기타보다 다른 역할 먼저, 최근 것). 계정 없는 명부 줄은 담임이면 T1002, 반이 있으면 T1001, 아니면 T1099.
  - 전화가 숫자 11자리면 010-0000-0000 모양으로.
- 넣기(새 DB, 한 묶음 · GO · 트랜잭션 문장 없음): 계정 짝 → 덮어쓰기/새로 → 유년부 소속(다른 정식 부서 소속이면 그대로, 임시 부서에 있었으면 옮김) → 명부 비우기 → 명부 줄 잇기/만들기 → 반 · 반 배정 → 감사 기록(`YuyunbuImport`) → 결과 표 2개(항목별 수 · 건너뛴 계정).
- 여러 번 돌려도 된다(두 번째는 "덮어씀"으로).
- 로컬 확인: 예전 표를 흉내 낸 DB 로 뽑기 → [SQL 실행] 시험 · 저장 → 예전 비밀번호로 로그인하면 유년부 홈.

## 운영 순서
1. 예전 DB(SSMS)에서 `yuyunbu-export.sql` 실행 → 결과를 모두 복사.
2. 새 사이트 플랫폼 ☰ › SQL 실행에 붙여 넣고 **[시험 실행]** → 결과 표 확인.
3. 맞으면 **[저장]**(SAVE).
4. 플랫폼 ☰ › 부서 관리자 규칙에서 [저장]을 한 번 눌러 옮긴 사람들에게 관리자 규칙을 적용.

## 2026-11-21 고침 — 임원 · 봉사 역할이 빠지던 것(사용자 "부장 · 부감 · 서기 역할이 다 빠져서 온다")
- 예전 DB 확인(`tools/sql/yuyunbu-role-check.sql`): DeptRoleUserAssoc 에 지도 2 · 부장 2 · 부감 1 · 서기 1 · 회계 1 이 있고, 반 배정 쪽(view_All_Person_2026)에는 보조 · 율동 · 영상 · 반주 · 새친구도 있다.
- 빠진 까닭: 역할을 DeptRoleUserAssoc 한 곳에서만 읽고, 계정 없는 사람은 담임이면 무조건 교사(T1002)로 정했다.
- 이제: 후보를 모아("DeptRoleUserAssoc" · "반 배정 역할" · 계정 없는 사람은 "담임 T1002 · 반 있음 T1001") **특별한 역할 먼저** 하나를 고른다 — 임원(지도 · 부장 · 부감 · 서기 · 회계 · 교장) → 봉사(보조 · 지원 · 율동 · 촬영 · 영상 · 반주 · 스텝) → 교사 → 새친구 → 학생 → 그 밖 → 기타. 임원 · 봉사도 새 사이트에서 반 담임을 맡을 수 있다(CanTeach).
- 로컬 확인(예전 표를 흉내 낸 DB): 부장 → T1005, 교사인데 반 배정엔 서기 → T1008, 계정 없는 부장 담임 → T1005(담임 배정 유지), 영상 → T1017.
- 다시 돌리기: 예전 DB 에서 `yuyunbu-export.sql` 을 다시 실행해 새 사이트 [SQL 실행]에 붙이면 같은 계정은 "덮어씀"으로 역할이 바로잡힌다(여러 번 돌려도 된다).
