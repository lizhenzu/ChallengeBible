# 0118 부서 사진첩

- 날짜: 2026-11-20 · 상태: 확정(사용자 "1 진행", 시안 `시안/사진첩-시안.png`, 논리 설계서는 사용자 제공)

## 결정(사용자 답)
- **사진만**(JPG · PNG · WEBP · GIF, 내용으로 확인). 동영상은 받지 않는다.
- 크기: 사진 한 장 20MB, 가로 · 세로 12,000 픽셀까지, 부서마다 5GB(설정 `Albums:QuotaMb`). 같은 앨범에 같은 사진(SHA-256)은 다시 안 올린다.
- 앨범 공개 범위: 누구나 · **로그인한 사람 모두(기본)** · 부서 사람만 · 관리자만. 내려받기는 **볼 수 있는 사람 모두**(앨범에서 끌 수 있음 — 끄면 부서 관리자만).
- 권한: 앨범 만들기 · 고치기 · 지우기 · 대표 사진 = 부서 관리자. 사진 올리기 = 교사 · 관리자. 사진 지우기 = 교사는 **본인이 올린 것만**, 관리자는 모두. 플랫폼 관리자는 모든 부서.
- 부서 홈: 최근 앨범 3개 카드(볼 수 있는 앨범이 없으면 숨김) + ☰ "사진첩".

## 설계
- 표 `app.Album`(TenantId, 제목 · 설명 · 촬영일 · 대표 사진 · 공개 범위 · 내려받기) 1 : N `app.Photo`(원본 · 썸네일 이름, 크기, 가로세로, 해시). RLS + 전역 필터로 부서 격리.
- 파일: `Albums:Dir`(없으면 `App_Data/albums`)`/{TenantId}/` 에 GUID 이름 원본 + `t_*.jpg` 썸네일(EXIF 회전 반영, 480px). wwwroot 밖 — `/{부서}/album/photo/{번호}` 가 부서 · 공개 범위 · 내려받기를 확인하고 연다. 다른 부서 주소로는 404.
- 올리기: 화면이 한 장씩 차례로 보낸다(파일별 진행률, 성공 · 대기 · 실패, 실패한 것만 다시, 취소). 성공한 사진은 바로 저장돼 화면을 떠나도 남는다.
- ZIP: 서버에 압축 파일을 만들지 않고 보내면서 압축(사진은 이미 압축돼 있어 저장만).
- 이미지 처리: SixLabors.ImageSharp 3.2.0(알려진 보안 문제 없는 판). 라이선스: Six Labors Split License — 비영리 · 연 매출 100만 달러 미만은 무료.
- 바꾼 기록: AuditLog `Album`.
