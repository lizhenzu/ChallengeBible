## 1. 일하는 방식 (사용자 규칙 — 꼭 지킨다)
- 한국어, **답변은 10줄 이하**(2026-11-26 사용자 지시). 질문은 **한 번에 하나**, 번호 선택지. 쉽게 설명.
- **작업 전에 어떤 모델이 좋은지 먼저 알려 주고, 사용자가 모델을 바꾸면 시작한다**(토큰 절약). 설계 · 어려운 결정 = Opus 5.5, 시안 · 구현 · 게시 = Sonnet 5.5, 단순 질문 = Haiku. 사용자는 `/model` 로 직접 바꾼다.
- **구현은 사용자가 「구현」이라고 할 때만, 게시는 「게시」라고 직접 말할 때만.** 사진 · 확인 답만으로는 게시하지 않는다(자동 권한 검사가 `main` 합치기 + 배포를 막는다 — 2026-11-27 실제로 막힘. 「게시」라고 하면 통과).

- 용어(2026-11-26 확정, `docs/concept/02_용어집.md` · `CLAUDE.md`): **메인화면**(= 예전 웰컴, `/{부서}/welcome`) · **홈**(= 도전!!! 성경말씀 부서 홈 `/{부서}`) · **첫 화면**(`/`). 「웰컴 · 소개 · 처음화면」은 쓰지 않는다. 「365축복기도」 full. 관리자 계정은 절대 지우지 않는다.

## 2. 배포 · 작업 절차 (바뀐 것 위주)
- 개발 브랜치 `ccr-bc03a6a2-v00n5k`(이 방). 커밋 → `git push origin HEAD:ccr-bc03a6a2-v00n5k` → (게시 말씀이 있으면) `git push origin HEAD:main` → `gh api -X POST repos/lizhenzu/ChallengeBible/actions/workflows/publish.yml/dispatches -f ref=main` → 실행 번호를 받아 `gh api .../actions/runs/{id}` 로 끝날 때까지 본다(약 4~5분).
- 게시 워크플로우가 **테스트(973여 개)를 먼저 돌리고 통과하면 배포**한다. 실패하면 배포는 안 된다 — 실패 줄은 `gh api .../jobs/{jobId}/logs | grep -E "Failed |error (CS|RZ)"` 로 본다.
- **이 방(클라우드)에는 .NET 이 없고 설치 사이트도 막혀 있다** → 로컬 테스트 불가. 컴파일 오류 · 테스트 실패는 게시 워크플로우가 처음으로 알려 준다(첫 시도에 실패하고 고쳐서 다시 올리는 일이 잦다). 테스트만 돌리는 워크플로우(`test.yml`)를 `main` 에 추가하려 했으나 자동 권한 검사가 막았다.
- Razor 에서 자주 낸 오류: `<form>` 같은 태그 도우미 안 속성에 `@(...)` 로 C# 넣기(RZ1031) · 같은 이름 지역 변수(CS0128) · 네임스페이스와 같은 이름의 형식(`WeeklyWord` → 별칭 `WeeklyWordRow` 사용) · JSON 의 한글이 `\uXXXX` 로 나옴(→ `JavaScriptEncoder.Create(UnicodeRanges.…)`).
- 화면 모양 확인: 클라우드에서 Playwright 로 정적 HTML 을 그려 원본 퍼블리시본과 픽셀 비교하는 방법을 썼다(CSS 변환 스크립트는 /tmp 라 사라짐 — 필요하면 다시: 퍼블리시본 CSS 를 `.wl` / `.bk` 범위로 가두고 클래스에 접두사를 붙이는 파이썬 파서).
- 운영 DB 변경은 `tools/sql/migrate-*-site.sql` 을 사용자가 사이트 SQL 화면에서 **게시 전에** 실행(저장 + 확인 글자 SAVE). 이번 `migrate-weekly-word-site.sql` 은 2026-11-27 10:17 에 실행 완료.
