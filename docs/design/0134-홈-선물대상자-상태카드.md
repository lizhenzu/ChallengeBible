# 0134 홈 선물 대상자·상태 카드 (C안 · 사람별 카드 + 3단계 눈금)

- 날짜: 2026-11-23 · 상태: 결정(사용자 "C안으로 구현 해줘")
- 관련: ADR 0094(선물 시스템 G-1 · G-3 · G-6 · R-297) · 0127(홈 교체로 보드 제거) · 0133(나의 도전 현황 통합 카드)
- 시안: `docs/design/시안/홈-선물대상자-상태카드-단독시안.html` (A · B · C 중 C 확정)

## 배경 — 왜 사라졌나

R-297로 만든 홈 카드 `누가 선물 받나요`(미션·개인 선물 통합 보드)를 ADR 0127의 dodan 홈 전면 교체 때 지웠다.
첫 화면(`/`)에는 애초에 없었다. 데이터(`GiftOrderService.BoardAsync`)와 전체 명단 화면 `/{slug}/gift-board` 는 남아 있었으므로
같은 조회를 홈 카드로 다시 붙인다.

## 결정

1. **자리** — 나의 도전 현황 카드 바로 아래, 가족팀 카드 위. 부서 홈(`/{slug}`)과 첫 화면(`/`) 모두.
2. **모양(C안)** — 사람마다 한 칸. 안에 이름 · 종류 딱지 · 선물 이름 · 3단계 눈금(골랐어요 → 샀어요 → 줬어요).
3. **상태 글자** — `골랐어요` / `샀어요` / `받았어요`(GiftStates Picked · Purchased · Delivered). 받은 줄은 옅은 초록 바탕(`--s1`) + 3칸 모두 채움.
4. **대상 범위** — `BoardAsync` 와 같다. 골랐어요 · 샀어요 + **받은 지 30일까지**(R-297), 생일 선물은 생일 주(일~토)에만.
5. **가격 없음** — 아이 · 학부모가 보는 화면이라 원 · 쿠팡 링크는 두지 않는다(R-297).
6. **개수** — 최대 3명, 전체가 더 있으면 `선물 대상자 N명 전체 보기 ›` → `/{slug}/gift-board`.
7. **없을 때** — `아직 선물 대상자가 없어요` + 무엇이 생기면 보이는지 한 줄. 손님에게는 이름 대신 `로그인하면 선물 준비 상태가 보여요`.
8. **조건** — 승인된 소속(`tenant.IsApproved`) · 임시 부서(로비) 아님. 미션을 꺼도 연다(통합 선물).

## 구현

- `Services/GiftOrderService.cs` — `GiftTargetRow`(Step · StateText · KindTone) · `GiftTargetBoard`(Rows · Total · Picked · Purchased · Delivered) · `TargetBoardAsync(take)` · `StateText(state)`.
  기존 `BoardAsync`(전체 명단 화면)는 그대로 둔다.
- `Pages/GiftTargetCardVm.cs` + `Pages/Shared/_GiftTargetCard.cshtml` — 두 화면이 같이 쓰는 부품.
- `TenantHomeModel.GiftBoard` · `IndexModel.GiftBoard` — 승인 소속 · 비로비일 때 `TargetBoardAsync(3)`.
- `landing.css` — `.vb-gift` · `.vb-gift.done` · `.vb-gift .st.s1/s2/s3` · `.vb-gift .dots` · `.vb-gift .k-*` · `.vb-giftfoot` · `.vb-gift-empty`.
- 테스트: `GiftOrderTests` 2개 추가 — ① 홈 카드의 사람별 카드 · 3단계 글자 · 가격 없음, [샀어요]→s2 · [줬어요]→s3 색 변화 ② 대상 없을 때 빈 안내 · 손님 안내.

## 하지 않은 것

- 관리 화면의 가격 · 쿠팡 링크 · 처리 버튼은 홈에 옮기지 않는다(관리 › 선물 그대로).
- 홈에서 바로 [샀어요] · [줬어요] 를 누르게 하지 않는다 — 처리는 관리 화면 한 곳에서만.
