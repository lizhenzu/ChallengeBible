# 선물 데이터 설계(ADR 0094, 2단계 — 논리 · 물리)

- 상태: **초안 — 사용자 확인 전** (2026-11-14)
- 근거: ADR 0094(결정 A ~ H + 정한 것 1 ~ 3), 업무 규칙 R-276 ~ R-299, 유년부 `AwardItem`(ProductID IDENTITY(1000,1) · ProductName · ProductDescription · IsHidden · UnitPrice · SourceType · ExternalUrl)
- 원칙: 업무 데이터는 TenantId(RLS + EF 전역 필터, D20) · 저장은 UTC · DB 현재 시각 함수 금지 · 금액 · 크레딧 기본값은 규칙(RuleSet)에서 읽는다.

## 1. 표 한눈에

| 표 | 무엇 | 부서 격리 |
|---|---|---|
| `app.GiftItem` | 상품(공통 · 부서). 번호 = 유년부 ProductID 그대로, 새 번호는 이어서 | 공통(NULL)은 모두 읽기, 부서 상품은 그 부서만 (콘텐츠와 같은 `fn_SharedRead/Write`) |
| `app.GiftItemHidden` | 부서가 숨긴 공통 상품 | `fn_Tenant` |
| `app.GiftSetting` | 부서 설정 한 줄(개인 상한 · 새친구 · 초대 · 생일 금액 범위) — 빈 칸 = 규칙 기본값 | `fn_Tenant` |
| `app.GiftCreditRate` | 부서 크레딧 → 금액 표(1,000 크레딧 단위) | `fn_Tenant` |
| `app.GiftReadingAmount` | 부서 완독 회차별 금액 표 | `fn_Tenant` |
| `app.Gift` | **선물 한 건**(모든 종류 같은 흐름) | `fn_Tenant` |
| `app.GiftLog` | 선물 한 건의 모든 동작(이력) | `fn_Tenant` |
| `app.GiftPointUse` | 개인 선물에 쓴 점수(그해) | `fn_Tenant` |
| `app.TeamAwardArchive` | 새해 초기화 때 옮겨 둔 지난해 시상 기록 | `fn_Tenant` |

가족팀 · 친구팀 단계별 **최대 금액**은 이미 있는 `DM2_FamilyMilestoneConfig.GiftAmount`(해마다 · 단계마다)를 그대로 쓴다(0093 · R-219). 표를 새로 만들지 않는다.

코드에 숫자를 쓰지 않기 위해 플랫폼 규칙 JSON 에 넣는다(예전 저장분에 없으면 아래 기본값, 0060 과 같은 방식).

## 3. 표 정의(물리)

### 3-1. `app.GiftItem` — 상품
| 칸 | 형식 | 설명 |
|---|---|---|
| `Id` | int, PK, IDENTITY | 유년부 ProductID 를 그대로(IDENTITY_INSERT), 옮긴 뒤 RESEED → 새 번호는 이어서(R-278) |
| `TenantId` | int NULL | NULL = 공통, 값 = 그 부서 상품(콘텐츠의 공용 · 부서 구분과 같다) |
| `SharedByTenantId` | int NULL | 공통에 올린 부서(그 부서와 플랫폼만 고침, R-277). 유년부 상품은 NULL |
| `Name` | nvarchar(100) | |
| `Description` | nvarchar(500) NULL | |
| `Price` | int | 원, ≥ 0 |
| `CoupangUrl` | nvarchar(1000) NULL | `coupang.com` 주소만(화면 검사). 비어 있으면 삭제 대상 |
| `Status` | varchar(10) | `Active` · `Review`(삭제 대상) · `Retired`(목록에서 내림) |
| `ReviewReason` | nvarchar(100) NULL | 삭제 대상인 까닭(쿠팡 링크 없음 · 쿠팡 아님 · 유년부 숨김) |
| `HasImage` | bit | `/images/AwardItem/{Id}.jpg` 가 있는가(없으면 기본 그림) |
| `CreatedUtc` · `UpdatedUtc` | datetime2(3) | 앱이 넣는다 |
| `UpdatedByUserName` | nvarchar(256) NULL | |
- 색인: (`TenantId`, `Status`), (`Status`, `Price`).
- 아이에게 보이는 목록(R-276) = `Status = Active` 이고 (`TenantId IS NULL` 이며 숨김에 없음) 또는 `TenantId = 이 부서`.

### 3-2. `app.GiftItemHidden`
`TenantId` · `GiftItemId` (PK 둘 다), `HiddenUtc`, `HiddenByUserName`.

### 3-3. `app.GiftSetting` (부서마다 한 줄, 없으면 모두 규칙 값)
`TenantId` PK, `PersonalCap` int NULL, `NewcomerMin` · `NewcomerMax` · `InviteMin` · `InviteMax` · `BirthdayMin` · `BirthdayMax` int NULL, `UpdatedUtc`, `UpdatedByUserName`.

### 3-4. `app.GiftCreditRate` · `app.GiftReadingAmount`
- `GiftCreditRate`: `TenantId` · `Credits`(1,000 단위, PK 둘 다) · `Amount`(원). 줄이 없는 크레딧은 1크레딧 = 1원(R-283).
- `GiftReadingAmount`: `TenantId` · `RoundNo`(PK 둘 다) · `Amount`. 표에 없는 회차는 마지막 줄, 표가 비면 규칙 값(R-289).

### 3-5. `app.Gift` — 선물 한 건(R-298)
| 칸 | 형식 | 설명 |
|---|---|---|
| `Id` | bigint, IDENTITY | (TenantId, Id) PK |
| `TenantId` | int | 비용 부서(완독은 완독한 때의 소속 부서) |
| `Kind` | varchar(10) | `Personal` · `Newcomer` · `Invite` · `Birthday` · `Reading` · `Family` · `Friend` |
| `Year` | smallint | 생긴 해(부서 날짜). 새해 초기화 · 총비용 기준 |
| `UserName` | nvarchar(256) NULL | 받는 사람 계정(개인 · 완독 · 친구팀 · 계정 있는 생일 · 초대) |
| `PersonId` | int NULL | 받는 사람 명부 줄(새친구 · 계정 없는 생일) |
| `FamilyTeamId` | int NULL | 가족팀 · 친구팀 |
| `SourceKey` | varchar(40) | 한 번만 생기게 하는 열쇠: 생일 `B2026`, 완독 `R2`, 팀 단계 `T1000`, 새친구 · 초대 `N{사람 번호}`, 개인 = 고른 차례 `P{번호}` |
| `State` | varchar(10) | `Open` · `Picked` · `Purchased` · `Delivered` · `Cancelled` · `Skipped` · `Expired` |
| `OpenFrom` · `OpenUntil` | date NULL | 고를 수 있는 기간(부서 날짜). 기한 없음 = NULL(새친구 · 초대). 다시 열기는 `OpenUntil` 을 오늘 + 7일로 |
| `MinAmount` · `MaxAmount` | int | 고를 수 있는 금액 범위(원), 생길 때의 부서 설정 · 규칙 값을 적어 둔다 |
| `GiftItemId` | int NULL | 고른 상품 |
| `ItemName` · `ItemPrice` · `ItemHasImage` | nvarchar(100) · int · bit NULL | **고른 때의 상품 모습**(내려도 이력 · 총비용이 그대로, R-279 · R-295) |
| `CreditsUsed` · `PointsUsed` · `PointsBurned` | int NULL | 개인 선물만(R-281) |
| `LinkToken` | char(32) NULL | 로그인 없는 링크(R-287). 새로 만들면 바꾼다. 유일 색인(NULL 제외) |
| `PickedUtc` · `PurchasedUtc` · `DeliveredUtc` | datetime2(3) NULL | |
| `CreatedUtc` | datetime2(3) | |
- 유일: (`TenantId`, `Kind`, 받는 쪽(`UserName` · `PersonId` · `FamilyTeamId`), `SourceKey`) — 같은 선물이 두 번 생기지 않게.
- 색인: (`TenantId`, `Year`, `State`), (`TenantId`, `UserName`), (`LinkToken`).

### 3-6. `app.GiftLog` — 이력(R-295)
`TenantId` · `Id` bigint IDENTITY (PK), `GiftId` bigint, `Action` varchar(12)(`Open` · `Pick` · `Change` · `Cancel` · `Purchase` · `Deliver` · `Undo` · `Reopen` · `Skip` · `Expire` · `Link`), `ActorUserName` nvarchar(256) NULL(링크로 고르면 NULL = "부모님 링크"), `AtUtc`, `ItemName` · `ItemPrice` NULL(그때 고른 것), `Detail` nvarchar(200) NULL.

### 3-7. `app.GiftPointUse` — 개인 선물에 쓴 점수(R-281)
`TenantId` · `Id`(PK), `UserName`, `Year`, `GiftId`, `PointsUsed`, `PointsBurned`, `FirstBonus` bit(그해 처음 5,000 을 이번에 썼는가), `CreatedUtc`. 취소(구매 전)는 줄을 지운다 — 해가 바뀐 뒤 취소는 지우지 않는다(R-282 · R-284).
- 남은 크레딧 = 규칙으로 계산: (그해 점수 − 쓴 점수)를 100점 단위로 바꾸고, 그해 처음 5,000 을 아직 안 썼으면 첫 100점은 5,000. 상한에서 자른다.

### 3-8. 새해 초기화(R-296)
- `app.GiftYearClose`: `Year` PK, `ClosedUtc`, `ClosedByUserName`.
- `app.TeamAwardArchive`: `DM2_TeamAward` 와 같은 칸 + `Year`. 초기화 때 `DM2_TeamAward` 를 여기로 옮기고 비운다(공유 표 `DM2_TeamAward` 는 키에 해가 없어 같은 팀 · 같은 단계가 새해에 다시 받을 수 없기 때문).
- 막기: 그해 `app.Gift` 에 `Open` · `Picked` · `Purchased` 가 하나라도 있으면 초기화 버튼이 막히고 부서별 건수를 보인다.

## 4. 유년부 상품 옮기기(SQL, 3단계 전에)
- 유년부 DB 의 `AwardItem` 을 읽어 `app.GiftItem` 에 **번호 그대로**(IDENTITY_INSERT) 넣는다. 공통(`TenantId = NULL`).
- `Status`: `IsHidden = 1` → `Review`(유년부 숨김), `ExternalUrl` 이 비었거나 `coupang.com` 이 아니면 → `Review`(까닭 적음), 나머지 `Active`. `HasImage` 는 처음엔 1(R-274 로 서버에 올린 이미지), 관리 화면에서 없는 것을 찾아 고친다.
- 옮긴 뒤 `DBCC CHECKIDENT` 로 새 번호를 유년부 마지막 번호 다음부터.
- 유년부 DB 는 다른 DB 라 **두 단계**: ① 유년부 쪽에서 상품을 내보내는 SQL(읽기만, 결과를 INSERT 문으로) → ② 챌린지 쪽에서 실행. (예전 `bookoverview-1-export-old.sql` · `-2-import-new.sql` 과 같은 방식)

## 5. 확인할 것(사용자)
1. 위 표 구성으로 갈지(특히 선물 한 건을 `app.Gift` **한 표**로 모든 종류를 다루는 것).
2. 새해 초기화 때 `DM2_TeamAward`(유년부와 같은 공유 표)를 비우고 지난해 표로 옮기는 것.
