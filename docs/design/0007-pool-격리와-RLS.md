# 0007. 격리 방식 — Pool (DB 1개 + TenantId + RLS)

- 상태: 확정 (2026-10-21)
- 원래 결정: D7
- 관련: 0018, 0020, R-131

## 맥락
멀티테넌트 격리 방식에는 영역마다 DB(Silo), 스키마 분리, 한 DB 공유(Pool)가 있다.
공유 호스팅(SmarterASP)에서 영역마다 DB 를 만드는 것은 비용 · 운영 부담이 크다.

## 결정
- **DB 1개**를 모든 영역이 함께 쓴다.
- 모든 **업무 데이터** 행은 `TenantId` 를 가진다.
- DB 수준 **행 수준 보안(RLS)** 으로 다른 영역의 행을 차단한다(SQL Server 2019 이상, 0018).

## 결과
- TenantId 가 **없는** 전역 데이터를 명확히 구분해야 한다. 지금 예상하는 전역 데이터:
  계정, 영역 자체, 공용 콘텐츠 라이브러리 · 퀴즈 문제 은행, 성경 본문 · 책 정보,
  플랫폼 기본 규칙, 감사 로그. (도메인 모델에서 확정)
- 인덱스는 TenantId 를 선두에 둔다(물리 설계).
- 플랫폼 관리자가 영역을 넘나드는 경로는 RLS 를 어떻게 통과할지 물리 설계에서 정하고,
  그 경로는 감사 로그를 남긴다(R-134).
- 한 영역의 장애 · 부하가 다른 영역에 영향을 줄 수 있음을 감수한다.
