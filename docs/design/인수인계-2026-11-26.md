## 1. 일하는 방식 (사용자 규칙 — 꼭 지킨다)
- 한국어, **짧게**(5~10줄). 한 번에 질문 하나, 번호 선택지.
- **구현은 사용자가 시킬 때만**(「구현」 · 「구현 후 게시」 · 「합치기만, 게시는 하지 마」). 말한 것이 질문인지 지시인지 헷갈리면 먼저 확인한다(지시로 오해해 작업했다가 혼난 적 있음).
- 화면은 **시안 먼저**(바뀌는 곳을 빨간 박스로). 내가 추천하면 묻지 않고 바로 시안으로 그린다.
- 게시 뒤에는 **폰에서 확인할 곳을 번호 붙인 폰 화면 그림**으로 주고, 답을 받을 때까지 다시 묻는다. 상자 · 화살표 흐름도는 「화면에 없다」고 거절당함 → 실제 폰 화면 모양에 번호.
- 구현 뒤에는 시안과 실제를 **스크린샷으로 맞춰 본 뒤** 게시한다(CSS 덮어쓰기로 시안과 달랐던 적 있음).
- 용어: 「365축복기도」 full. 관리자(SuperAdmin / 부서 Admin) 계정은 절대 지우지 않는다. 비밀 값은 Git 에 두지 않는다.
- 기준 문서: `CLAUDE.md`, `docs/concept/`, 화면 통일 변경 기록 `docs/design/0141-화면-통일-기준표.md`(56판까지).

## 4. 지금 할 일: 주보 화면 UX 새 시안
- 대상: 로그인 안 한 사람이 보는 `/{부서}/bulletin`(`Pages/Bulletin/Index.cshtml`, `wwwroot/css/bulletin.css`). 현재: 머리말 「‹ 주보」 + 본문 「‹ 부서 홈」(뒤로가기 두 개), 사진이 카드 속에 작게, 누르면 새 탭, 지난 주보는 목록.
- 사용자가 준 참고: 예전 「주보게시판」(사진 화면 폭 가득, 아래로 이어지는 글, 좋아요 · 댓글, 전체 N · 오늘 N) 과 교회 「새로운주보」(2열 작은 그림 + 날짜 막대).
- **이전에 그린 시안 3개(`docs/design/시안/주보-UX개선*.png`)는 사용자가 「무시하고 새로 하고 싶다」고 했다.** 그 틀(크게 보기 · 저장 · 공유, 2열 그리드 등)을 이어받지 말고 사용자에게 먼저 **무엇이 불편한지 · 원하는 방향**을 한 가지씩 물어본 뒤 새로 그린다.
- 구현은 사용자가 시킬 때만.
