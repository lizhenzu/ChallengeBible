# 0090. 유년부와 공유 표 구조

- 상태: 확정 (2026-11-10, 사용자 지시 — 유년부 지시서 07 · 부록 08 대로)
- 근거: YuYunBu `docs/challenge-bible/07_유년부_동일구조_이관_지시서.md`, `08_공유표_정의.md`
- 고치는 ADR: 0004 · 0010 · 0027 · 0029 · 0039 ~ 0042 · 0050 · 0060 · 0083 · 0084
- 관련: 0007 · 0020(영역 격리), 0055(로그인 키 저장), 0058 · 0066(진급), 0065(온가족)

## 맥락
유년부 사이트의 회원 · 역할 · 가족팀 · 시상 · 미션 · 통독 기록을 변환 없이 매일 새벽 "유년부 영역"에 덮어쓰고, 유년부 로직이 바뀌면 그대로 옮겨 오려 한다. 그러려면 표 구조가 같아야 한다. ChallengeBible 은 아직 사용자가 없어 기존 표와 시험 데이터를 지워도 된다(사용자 확인, 2026-11-10).

## 결정
1. 공유 표는 08 부록과 표 · 칸 이름, 형식, 빈 값, 검사, 키가 같다. B · C · D 묶음에만 `TenantId INT NOT NULL` 을 더하고, 기본 키 · 유일 색인 · 외래키 앞에 `TenantId` 를 붙인다. 예외는 `UX_DM2_FamilyMember_UserName`(전역 유일)이다.
2. 사람은 **아이디(UserName)** 로 가리킨다. `AccountId` · `ParticipantId` · `MembershipId` 칸은 모든 표에서 없앤다.
3. 계정은 `Identity.*` 표다. 로그인 칸은 하나이고 아이디 또는 이메일을 받는다. 아이디는 플랫폼 관리자만 바꾸며, 바꿀 때 모든 기록의 아이디를 함께 고친다.
4. 부서 소속은 `DeptRoleUserAssoc.TenantId` 다. 한 사람은 한 부서에만 속한다. 대기 중인 신청은 `SignupApplication` 에 있다.
5. 미션 기본 점수 · 인정 기간 · 횟수는 모든 부서가 같다. 부서가 정하는 것은 시상 기준 점수(`DM2_FamilyMilestoneConfig`)뿐이다.
6. 점수 합계는 저장하지 않고 `DM2_MissionActivity.Points` 를 더해 계산한다.
7. 시상 기록(`DM2_TeamAward` · `DM2_FamilyMilestoneHidden`)이 있는 팀은 나가기 · 내보내기 · 역할 바꾸기가 막힌다.
8. 통독 5표와 `Identity.*` 에는 `TenantId` 가 없고 부서 필터도 받지 않는다.

## 지시서에 없어 이 방에서 정한 것
| 항목 | 결정 | 이유 |
|---|---|---|
| 현재 시각 기본값 | 08 의 `getdate()` · `sysdatetime()` 기본값은 **두지 않는다.** 앱이 항상 값을 넣는다 | 프로젝트 원칙(DB 현재 시각 함수 금지). 07 의 "한 글자도" 대상은 칸 이름 · 형식 · 빈 값 · 검사이고 기본값은 아니다. 숫자 · 문자 기본값은 그대로 둔다 |
| 점수 값의 자리 | `app.PlatformRuleSetVersion` 은 남기고 `app.TenantRuleSetVersion` 만 지운다 | "점수 값은 코드에 쓰지 않는다" 원칙과 "플랫폼 고정"을 함께 지킨다 |
| `DeptRoleUserAssoc` · `CodeData` 키 | PK (TenantId, Id). `UserId` 유일 색인은 **두지 않고** 앱이 한 트랜잭션으로 지키고 넣는다 | 08 에 키가 없고, 유년부는 회원 190명에 241줄이라 유일 색인이면 전송이 깨진다 |
| 학부모의 소속 | `RoleCode = NULL` 인 한 줄로 둔다 | 소속을 이 표로 정하므로 줄이 있어야 한다. 유년부는 학부모 줄이 없다(아래 미해결) |
| 관리 권한 | `Identity.Role`: SuperAdmin = 플랫폼 관리자, Admin = 소속 부서의 관리자, Moderator, Basic = 일반 | 한 사람 한 부서이므로 전역 역할 + 소속 부서로 정해진다. 교사 · 학생 · 학부모는 `RoleCode` 로 판단한다 |
| Identity 에 없는 계정 값 | `app.UserSetting`(UserName, MustChangePassword, LastTenantId, ReadingTheme) 을 새로 둔다. 전송 대상이 아니다 | `Identity.User` 칸은 바꿀 수 없다 |
| 표시 이름 | `LastName + FirstName`(유년부와 같다). 가입은 칸 하나라 `FirstName` 에 넣는다 | 유년부 전송 데이터와 표시가 같아진다 |
| 로그인 키 표 | `app.DataProtectionKey`(0055)는 **남긴다** | 회원 정보가 아니라 쿠키 암호 키다. Identity 가 대신하지 않는다 |
| 지침의 "다른 표" | `GuardianLink`, `PromotionRequest`, `TenantSeason`, 콘텐츠의 작성자 칸, `AuditLog`, `Outbox` 는 표를 두고 사람 칸만 아이디로 바꾼다 | 07 의 5장 끝 문단 |
| 통독 기록의 개인 격리 | 부서 필터는 없지만 "본인 + 볼 권한" RLS(R-159)는 아이디 기준으로 유지한다 | 07 이 뺀 것은 부서 필터뿐이다 |

## 결과
- 지워지는 기능 값: 개인 시상 도달 기록과 "나중에" 표시(`MilestoneReached`)는 없어지고 계산으로 대신한다. 온가족 표(0065)도 없어진다. 한 사람이 여러 부서에 동시에 속하던 방식(0027)이 끝난다.
- 세션 값은 `TenantId` · `UserName` · `UserId` · `PlatformScope` 가 된다(`DeptRoleUserAssoc` 는 아이디가 아니라 `UserId` 를 가진다).

## 구현하며 정한 것 (2026-11-10)
- 유년부에 없어서 없앤 것: 소속 정지 · 해제, 반(그룹 라벨), 한 사람의 여러 역할.
- 미션은 소속이면 누구나 한다(유년부와 같다). 명단 · 홈의 "참여자"는 학생(T1001)이다.
- 축하 단계 도달 기록은 저장하지 않는다. 이번 점수로 합계가 단계를 넘는 순간을 계산한다.
- 절 읽음 표시는 진행 중 회차의 `DM2_ReadingVerse` 다(회차가 없으면 1회차를 연다). 장 완료를 풀면 함께 풀린다.
- 가입 아이디는 이메일의 @ 앞부분이다(유년부와 같다). 겹치면 가입할 수 없다.
- `app.UserSetting` 칸: MustChangePassword, PhotoPath, LastTenantId, ReadingTheme, MissionTheme, FamilyInvitesSnoozedAt.

## 미해결 (유년부 방에 전달)
- 유년부 학부모는 `DeptRoleUserAssoc` 에 줄이 없어, 07 의 7장 "유년부 소속 = 그 표에 있는 아이디" 기준에서 빠진다. 받는 창구를 만들기 전에 정해야 한다.
- 유년부의 시각 칸은 서버 현지 시각이고 ChallengeBible 은 UTC 다. 변환 없이 받으면 유년부 영역의 시각만 다른 기준이 된다. `MissionDate` 등 날짜 칸은 영향이 없다.
