# 도메인 모델 (초안)

- 상태: 초안 (2026-10-22)
- 기준: 02 용어집, 03 업무 규칙, 05 금지 사항, ADR 0001 ~ 0033
- 다음 단계: 논리 설계(ERD, 고유 제약, 테넌트 키 규칙)

## 1. 데이터 범위 3종

모든 데이터는 아래 셋 중 하나에 속한다. 범위가 격리 조건(RLS + 전역 필터, 0020)을 정한다.

| 범위 | 키 | 격리 조건 | 예 |
|---|---|---|---|
| **영역** | TenantId | 현재 영역 = 행의 TenantId | 소속, 참여자, 수행 기록, 점수, 가족팀, 영역 설정, 덮어쓰기 콘텐츠 |
| **계정** | AccountId | 로그인 계정 = 행의 AccountId (0029) | 성경 읽음 표시, 책갈피 |
| **플랫폼** | (없음) | 읽기는 공유, 쓰기는 플랫폼 관리자만 | 계정, 영역, 공용 콘텐츠, 성경 본문, 플랫폼 기본 규칙, 감사 로그 |
| 예외 | Source · TargetTenantId | 현재 영역이 둘 중 하나 (0030) | 진급 요청 |

## 2. 컨텍스트 경계

```
┌ 테넌시 ─────────────┐   ┌ 콘텐츠 ──────────────┐
│ 계정 · 영역 · 소속   │   │ 성경 본문(참조)        │
│ 참여자 · 보호 관계   │   │ 공용 콘텐츠 · 덮어쓰기  │
│ 영역 설정 · 시즌     │   │ 퀴즈 문제 은행          │
│ 진급 요청 · 감사 로그│   └──────────┬───────────┘
└─────────┬──────────┘              │ 콘텐츠 결정(R-120)
          │ 참여자 · 규칙 · 시즌       ▼
          ▼                ┌ 미션 · 점수 ──────────┐
┌ 성경 읽기(계정) ──┐       │ 수행 기록 · 퀴즈 시도   │──▶ 이벤트 ──▶ 외부
│ 읽음 표시 · 책갈피│       │ 점수 원장 · 집계        │
└──────────────────┘       │ 축하 단계 도달          │
                           └──────────┬───────────┘
                                      │ 시즌 점수
                                      ▼
                           ┌ 가족 · 순위 ──────────┐
                           │ 가족팀 · 구성원 · 단계  │
                           │ 순위(조회 모델)          │
                           └──────────────────────┘
```

화살표는 의존 방향이다. 미션 · 점수는 가족 · 순위를 모른다(X-16). 가족 · 순위는 시즌 점수를 읽기만 한다.

## 3. 테넌시 컨텍스트

### 계정 Account — 집합 루트, 플랫폼 범위
- 아이디(로그인용, 바꿀 수 있음), 비밀번호 해시, 이름(또는 별명), 프로필 사진, 플랫폼 관리자 여부, 마지막 사용 영역(R-135)
- 아이디는 **어떤 기록의 키로도 쓰지 않는다**(X-01). 기록은 AccountId · ParticipantId 로만 가리킨다.
- 만 14세 미만 정보 최소화: 전화 · 생일 · 주소 속성 없음(R-137).

### 영역 Tenant — 집합 루트, 플랫폼 범위
- 영역 코드(TenantSlug, 고유, 주소 경로 — 0008), 이름, 시간대(기본 Asia/Seoul), 상태(운영 · 정지)
- 영역 설정(아래)을 가진다.

### 소속 Membership — 집합 루트, 영역 범위 (0027)
- (AccountId, TenantId) **고유**
- 상태: 신청 → 승인 → 정지 / 해제, 진급 대기(0026), 거절
- 역할 목록: 참여자 · 보호자 · 교사 · 영역 관리자 (여러 개)
- 그룹 라벨(선택, 표시 · 필터만)
- 불변식
  - 승인 상태가 아니면 어떤 역할도 쓸 수 없다(R-130).
  - 보호자 동의 확인은 없다(0031). 승인 + 참여자 역할이면 미션을 저장할 수 있다.
  - 역할 이름 · 계정 이름으로 권한을 추측하지 않는다(X-10, X-11).

### 참여자 Participant — 엔터티, 영역 범위
- ParticipantId(영역 안 점수 주체의 **유일한 키**), MembershipId(1:1)
- 소속에 참여자 역할이 처음 붙을 때 생긴다. 역할을 빼면 비활성(기록 유지), 다시 붙이면 같은 참여자를 다시 쓴다.
- 이름 · 사진은 계정에서 읽는다(복사하지 않음).

### 보호 관계 GuardianLink — 엔터티, 영역 범위
- (보호자 MembershipId, 참여자 ParticipantId) 고유. 영역 관리자가 만든다(0006).
- 보호자는 연결된 참여자의 기록만 본다(R-132). 자기 자신과 연결할 수는 없다.

### 영역 설정 TenantSettings — 값 객체 묶음, 영역 범위
- **규칙 설정 RuleSet**(0010): 플랫폼 기본 규칙 + 영역 덮어쓰기 = 유효 규칙
  - 키: 인정 기간, 미션 항목별(사용 여부 · 표시 이름 · 점수 — 0032), 퀴즈 시도 횟수, 축하 단계 목록, 목표 점수, 가족 단계 목록, 주 시작 요일
  - 불변식: 미션(말씀 · 기도 · 퀴즈 · 암송)마다 켜진 항목이 최소 1개(0032)
  - 버전을 가진다. 바꿀 때마다 새 버전 + 변경 이력(누가, 언제, 무엇).
- **기능 스위치 FeatureToggle**: 순위, 가족팀, 번역 대조
- **대표 색**: 정해 둔 색 목록 중 하나(0033)
- **서비스 이름 · 짧은 이름**: 비우면 플랫폼 기본 "도전!!!성경말씀" · "도전성경"(0037, 0038)
- **시즌 Season**(0028): 연도별 시작일. 시즌 = (TenantId, 연도) → [시작일, 12월 31일]. 기본 1월 1일.

### 진급 요청 PromotionRequest — 집합 루트, 예외 범위 (0026, 0030)
- AccountId, Source(TenantId, MembershipId), TargetTenantId, 상태(대기 · 승인 · 거절), 요청자 · 처리자 · 일시
- 승인 = 새 소속 활성화 + 이전 영역 삭제를 **한 트랜잭션**으로. 삭제 범위는 6절.

### 감사 로그 AuditLog — 플랫폼 범위, 추가만
- 누가, 언제(UTC), 어느 영역, 무엇: 영역 진입, 대리 접속, 설정 변경, 진급 승인 처리, 읽음 기록 강제 삭제(R-134, 0029)

## 4. 콘텐츠 컨텍스트

### 성경 본문 — 참조 데이터, 플랫폼 범위
- 번역본, 책(순서 · 이름 · 소개 — R-116), 절(번역본, 책, 장, 절, 본문)
- 값 객체 **구절 범위 VerseRange**: 책, 시작 장:절, 끝 장:절(여러 장 가능). 끝 ≥ 시작.

### 콘텐츠 4종 — 집합 루트
공통 속성: 소유(공용 = 플랫폼 / 덮어쓰기 = 영역), 종류, 공개 여부(초안 · 공개 — R-123), 개정 번호.

| 종류 | 날짜 키 | 내용 |
|---|---|---|
| 오늘의 말씀 DailyWord | 노출일 1일 | 구절 범위, 요약, 해설, 질문(하위), 영상 구간(하위, 최대 5 — R-117) |
| 오늘의 기도 DailyPrayer | 공용: 매달 날짜 번호(1 ~ 31) · 부서: 노출일 1일 (0053) | 성품 이름, `{이름}` 자리가 있는 기도문 문단, 근거 구절 범위 (0047) |
| 오늘의 퀴즈 DailyQuiz | 노출일 1일 | 문제, 배경 설명, 형식(객관식 · 주관식), 보기(하위, ID), 정답(보기 ID 또는 허용 답 목록), 해설 |
| 이번 주 암송 WeeklyVerse | 기간 [시작일, 종료일] | 구절 범위, 공과 정보 |

- 불변식: 같은 소유 · 종류 · 날짜에 **최대 1건**(R-121, X-18). 암송은 같은 소유 안에서 기간이 겹치지 않는다.
- 거대한 가로 표 금지: 영상 구간 · 질문 · 보기는 하위 엔터티(X-19).
- **수정 = 새 개정**. 이미 수행 기록이 가리키는 개정은 바꾸지 않는다(R-124).

### 콘텐츠 결정 ContentResolver — 도메인 서비스
- (영역, 종류, 날짜) → 공개된 덮어쓰기가 있으면 그것, 없으면 공개된 공용, 둘 다 없으면 "없음"(R-120, R-122).
- 날짜는 항상 **영역 시간대의 날짜**로 받는다.

### 퀴즈 문제 은행 QuizBank — 플랫폼 범위
- 문제 저장소. 오늘의 퀴즈를 만들 때 복사해 쓴다(은행 수정이 지난 퀴즈를 바꾸지 않게).

## 5. 미션 · 점수 컨텍스트

### 값 객체
- **미션 대상일 MissionDate**: 날짜만. 영역 시간대 기준(R-02). 수행 시각(UTC)과 별개.
- **미션 항목 MissionItem**: 말씀.나 · 말씀.부모님께 · 기도.나 · 기도.부모님 · 기도.친구 · 퀴즈.정답 · 암송
- **오늘 Today**: (영역 시간대, 현재 UTC) → 날짜. 현재 시각은 앱의 시계 하나에서만 얻는다(X-09, DB 시각 함수 금지).

### 수행 기록 Activity — 집합 루트, 영역 범위
- ParticipantId, MissionItem, 미션 대상일, 수행 시각(UTC), 콘텐츠 ID · 개정, 얻은 점수
- 고유
  - 말씀 · 기도 · 퀴즈: (ParticipantId, 미션 대상일, MissionItem) — 하루 · 항목당 1건(R-61, X-04)
  - 암송: (ParticipantId, 암송 콘텐츠 ID) — 그 주 1번(R-51). 미션 대상일은 **실제 수행일**(0024, R-53)
- 저장은 멱등: 이미 있으면 새로 만들지 않고 점수 0 으로 응답(R-21, R-31, R-65)
- 수행 가능 검사(서버, R-13)
  1. 승인된 소속 + 참여자 역할(R-130, 0031)
  2. 미래 아님(R-11), 인정 기간 안(R-10), 시즌 시작일 이후(0028)
  3. 그 날짜에 콘텐츠가 있음(R-22)
  4. 그 항목이 규칙에서 켜져 있을 때만(R-30, 0032)
- 미션 완료 = 켜진 항목 중 하나라도 수행(R-32, 0032). 완주일 판단(0023)도 이 기준.

### 퀴즈 시도 QuizAttempt — 엔터티, 영역 범위
- (ParticipantId, 미션 대상일, 시도 번호) 고유. 고른 보기 ID 또는 입력 답, 정답 여부(R-42)
- 불변식: 시도 번호 ≤ 규칙의 시도 횟수, 이미 정답이면 더 시도 불가(R-41)
- 판정은 서버에서: 객관식은 보기 ID, 주관식은 정규화(공백 · 대소문자) 후 허용 답 목록과 비교(R-43, X-08)
- 정답이면 같은 트랜잭션에서 수행 기록(퀴즈.정답)을 만든다.

### 점수 원장 PointLedger — 추가만, 영역 범위
- 한 줄 = (ParticipantId, 미션 대상일, MissionItem, 점수, 규칙 버전, 원인 Activity ID)
- 수행 기록과 **같은 트랜잭션**에서 쓴다(R-63). 점수는 당시 규칙 값으로 고정(R-64).
- 점수 0 인 항목(기도.친구)도 수행 기록은 남지만 원장 줄은 쓰지 않는다.

### 집계 — 조회 모델, 영역 범위 (X-03)
- **하루 점수 DailyPoint**: (ParticipantId, 날짜) → 말씀 · 기도 · 퀴즈 · 암송 · 합계. 원장 기록 때 증분 갱신.
- **시즌 점수 SeasonPoint**: (ParticipantId, 연도) → 합계, 마지막 점수일, 연속 참여일(R-83). 시즌 시작일 변경 시 다시 계산(0028).
- 완주일 · 달력 · 최근 7일은 하루 점수 + 콘텐츠 유무 + 그 주 암송 여부에서 계산(R-70 ~ R-74, R-72).
- 집계는 원장에서 언제든 다시 만들 수 있어야 한다(원장이 근거).

### 축하 단계 도달 MilestoneReached — 영역 범위
- (ParticipantId, 연도, 단계 점수) 고유 — 시즌당 한 번(R-101)
- 점수 기록 직후와 미션 홈을 열 때 검사(R-101, R-102). 숨김 기한(1 · 3 · 7일, R-103)을 가진다.

## 6. 진급 — 옮긴 뒤 삭제 (0022, 0026, 0029 → **0066**)

승인 시 한 트랜잭션에서:
1. 새 영역 소속 · 참여자를 만든다(지금과 같음).
2. **옮기기(0066)**: 새 영역에 참여자가 생기면, 이전 영역의 수행 기록 · 점수 원장 · 퀴즈 시도 · 축하 단계 도달을 **날짜 그대로** 새 영역 참여자로 복사한다.
   방식은 임시 부서 옮기기(0064, R-174)와 같은 도메인 서비스 **기록 옮기기 RecordMover** — 새 영역에 같은 날 · 같은 항목(암송은 같은 주)이 있으면 새 영역 것을 남기고 건너뜀, 퀴즈 시도는 그날 시도가 없을 때만, 축하 단계는 (해 · 단계)가 없을 때만.
   - 옮긴 수행 기록은 이전 영역의 부서 콘텐츠(부서 기도 · 부서 암송)를 가리킬 수 있다(콘텐츠 FK 는 단일 키라 허용). 화면은 내용을 못 읽으면 "지난 부서 콘텐츠"로 보인다.
   - 새 영역에서 참여자 역할 없이(보호자로만) 진급하면 옮기지 않는다(점수 주인이 없음) — 이전 영역 기록은 그대로 지워진다.
3. **지우기**: 이전 영역에서 그 계정과 관련된 소속, 참여자, 보호 관계(양쪽), 수행 기록, 퀴즈 시도, 점수 원장, 하루 · 시즌 집계, 축하 단계 도달, 가족팀 구성원을 지운다.

지우지 않는 것: 계정, 성경 읽음 표시 · 책갈피 · 통독(0029, R-158), 감사 로그, 진급 요청 자체(승인 상태로 남김), 온가족 구성원 자리(계정 범위, 7-2).
옮긴 점수는 새 영역의 시즌 · 순위 · 축하 단계 · 가족팀 합산에 날짜대로 들어간다(새 영역의 지금 시즌 날짜에 든 것만 이번 시즌).

## 7. 가족 · 순위 컨텍스트 (기능 스위치)

### 가족팀 FamilyTeam — 집합 루트, 영역 범위
- 이름(비면 "{대표 학생 이름} 가족" — R-93), 메모, 활성 여부
- 구성원 FamilyMember: ParticipantId, 관계(학생 · 엄마 · 아빠 · 할머니 · 할아버지 · 기타), 표시 순서, 활성 여부
- 불변식: 구성원은 같은 영역의 참여자만(R-90, D12). 한 참여자는 한 연도에 활성 팀 **하나**(R-91).
- 팀 점수 = 활성 구성원 시즌 점수의 단순 합(R-92). 저장하지 않고 시즌 점수에서 계산.

### 가족 단계 도달 · 단계 숨김
- 가족 단계 목록은 규칙 설정에 있다(R-96).
- (가족팀, 연도, 단계 점수) 도달 기록 고유. 관리자 숨김(MilestoneDismiss)은 (가족팀, 단계) 고유(R-97).

### 순위 — 조회 모델
- 시즌 점수 > 0 인 참여자, 점수 내림차순 · 이름순(R-80). 달성률 = 시즌 점수 ÷ 목표 점수, 0 ~ 100%(R-81, R-82).
- 사용자마다 계산하지 않고 시즌 점수 집계를 한 번에 읽는다(X-03).

### 시상 부서 — 계정 속성 (0046 → 0065, R-179)
- Account.FamilyTenantId: 부모가 참여자 · 가족팀 구성원이 되는 영역 하나. **플랫폼 관리자가 정한다**(부모는 보기만).
- 불변식(지금과 같음): 보호자 계정은 시상 부서 밖에서 참여자 역할 · 가족팀 구성원이 될 수 없다. 정하기 전(NULL)에는 어디서도 안 된다.
- 바꾸면 이전 영역의 참여자 역할 · 가족팀 자리를 멈춘다(기록은 남김). 감사 로그 `FamilyTenantSet`.

## 7-2. 온가족 컨텍스트 (계정 범위 — 영역 밖, 0065)

가족팀(7절)과 **별개**다. 가족팀은 시상, 온가족은 부서를 넘는 총점 **보기만**. 미션 · 점수 · 가족팀은 온가족을 모른다(의존 방향: 온가족 → 점수 읽기만).

### 온가족 Family — 집합 루트, 플랫폼 범위(TenantId 없음)
- 이름(선택, 비면 "{대표 구성원 이름} 온가족" — 대표 = 관계가 학생인 첫 구성원, 없으면 첫 구성원), 만든 때 · 만든 사람
- 구성원 FamilyLink: AccountId, 관계(학생 · 엄마 · 아빠 · 할머니 · 할아버지 · 기타 — 가족팀과 같은 목록), 표시 순서, 넣은 때 · 넣은 사람
- 불변식
  - 한 계정은 **온가족 하나에만**(R-175). 빼면 행을 지운다(감사 로그가 이력).
  - 묶기 · 빼기 · 해체 · 이름 · 관계 · 순서는 **플랫폼 관리자만**(R-175). 구성원이 0 명이 되면 해체.
  - 플랫폼 관리자 계정도 구성원이 될 수 있다(가족이면).

### 온가족 신청 FamilyRequest — 집합 루트, 플랫폼 범위 (R-176)
- 신청한 계정, 내용(자녀 이름 · 교회 · 부서 등 자유 글, 500자), 상태(신청 · 승인 · 거절), 처리자 · 일시, 결과 온가족
- 불변식: 한 계정은 처리 안 된 신청 **하나**만. 승인은 플랫폼 관리자가 실제 계정을 찾아 묶는 일과 함께 한다(신청 글로 자동 연결하지 않음).

### 온가족 총점 FamilyTotal — 조회 모델 (R-177, R-178)
- 구성원 AccountId → 그 계정의 모든 영역 참여자 → 점수 원장 합(**처음부터 누적**, 날짜 제한 없음). 구성원별 합 · 마지막 점수일 · 영역 이름.
- 임시 부서(0064)는 승인 때 기록을 **복사**하고 임시 쪽도 남기므로, **멈춘(옮겨 간) 임시 부서 소속의 원장은 빼고** 센다(두 번 세지 않게). 아직 임시 부서에 있는 사람은 센다.
- 참여자 역할을 뺀(비활성) 참여자의 원장도 센다(얻은 점수는 그대로).
- 시상 · 축하 단계 · 순위에 쓰지 않는다. 저장하지 않고 볼 때 계산한다(가족 수가 적음 — 느려지면 그때 캐시).
- 보는 사람별 모양: 구성원 본인 · 플랫폼 관리자 = 구성원별 전부, 영역 관리자 = 총점 + **자기 영역 구성원만 이름**(나머지는 "다른 부서 1명"처럼 수만).

## 8. 성경 읽기 컨텍스트 (계정 범위, 0029)

- **절 읽음 표시**: (AccountId, 번역본 무관 절 위치 = 책 · 장 · 절) 고유, 읽은 날짜(UTC). 멱등 `PUT` · `DELETE`(X-17).
- **책갈피**: (AccountId, 책 · 장 · 절) 고유.
- 점수와 무관(R-113). 2차 통독률(0025)의 근거.

## 8-2. 성경통독 컨텍스트 (계정 범위, 0039 · 0040)

- 영역은 프로그램(성경말씀 `Mission` · 성경통독 `Reading`)을 켠다. 최소 하나(R-150).
- **통독 회차 ReadingRound** — 집합 루트, 계정 범위
  - (AccountId, 회차 번호) 고유, 시작 · 완료 · 닫힘 시각
  - 불변식: 계정마다 진행 중(완료 · 닫힘 아님) 회차는 하나(R-153)
  - 1,189장을 모두 읽으면 완료 + 다음 회차 시작. 본인이 새 회차를 시작하면 현재 회차는 닫힘(R-154)
- **장 읽음 ChapterRead** — 회차 안의 엔터티: (AccountId, 회차, 책, 장) 고유, 읽은 시각(UTC)
  - 장을 읽으면 그 장의 절 읽음 표시(8절)도 기록(R-152, 한 방향)
- 보여 주는 값: 진도율 · 완독 횟수 · 오늘 읽은 장 수 · 연속 읽은 날(R-155, R-156). 점수 없음(R-157).
- 영역 관리자 · 교사는 자기 영역 소속원의 요약만 본다(R-159).
