# 0030. 진급 요청은 플랫폼 범위 기록, 두 영역이 각자 자기 쪽만 본다

- 상태: 확정 (2026-10-22, 사용자와 합의)
- 보완 대상: 0026
- 관련: 0007, 0020, 0022, R-139

## 맥락
0026 은 진급 요청(PromotionRequest)이 두 영역에 걸친 기록이라, 어느 TenantId 로 두고 RLS 를 어떻게 통과할지
도메인 모델에서 정하라고 남겼다. 승인 시 이전 영역 데이터를 지우는 처리는 새 영역 관리자의 권한으로 실행되지만,
새 영역 관리자는 이전 영역을 볼 수 없다.

## 결정
1. 진급 요청은 TenantId 하나가 아니라 **SourceTenantId · TargetTenantId 두 개**를 가진 플랫폼 범위 기록이다.
2. RLS · 전역 필터 조건: 현재 영역이 **Source 또는 Target 인 행만** 보인다. 각 영역 화면은 필요한 열만 보여 준다
   (Source 쪽: 대상 영역 이름 · 상태 / Target 쪽: 계정 이름 · 이전 영역 이름 · 상태).
3. 새 영역 관리자의 **승인 처리는 "시스템 작업"** 으로 실행한다. 이 작업만 이전 영역의 테넌트 컨텍스트로 전환해
   삭제를 수행하며, 새 소속 활성화와 한 트랜잭션으로 묶는다(0026). 실행 사실은 감사 로그에 남긴다.
4. 시스템 작업은 코드에서 한 곳(진급 승인 처리기)만 쓸 수 있게 한다. 일반 요청 경로에서는 테넌트 컨텍스트를 바꿀 수 없다.

## 결과
- 어느 영역도 상대 영역의 다른 데이터를 볼 수 없다. 공유되는 것은 진급 요청 한 줄뿐이다.
- 진급 대기 동안 새 영역에는 "진급 대기" 상태의 소속이 미리 생긴다(0026). 거절하면 그 소속과 요청을 거절 상태로 닫는다.
- 같은 계정 · 같은 Source 에 대해 진행 중 요청은 1건만 둔다(고유).
